# 开发说明

当前版本设计见 [运行时设计](DESIGN-agent-runtime.md)，模块划分见 [架构](ARCHITECTURE.md)。此文件只保留持续适用的开发约定，不重复版本流水账。

## 工作约定

- 以代码和实际测试为准，中文沟通；优先简单实现，避免反复扩大防御和审批范围。
- agent 是持续存在的个体。会话、工具调用、异步任务都明确绑定 agent 与来源。
- 内核继续用 C，网关用 Go；控制常驻进程、缓存、输出和队列的内存占用。
- 用户要求当前工作不使用子代理；需要改变时以用户的新指示为准。
- 测试使用临时 NANO_HOME、HOME、USERPROFILE 和模型替身，不启动真实机器人或真实模型，不改正式服务、任务计划、PATH、配置及 data。
- 真实模型或桌面专项按明确授权运行，只清理本次创建且身份已核实的进程。
- 新文档只在已有主题无法容纳时创建。设计写当前规则，使用说明写入口；实施过程和已解决问题留在 Git 提交，不追加评审轮次和重复完成清单。

## 验证入口

按改动范围选择验证；只改文档时检查链接和 diff，不重复跑产品全套。

~~~sh
make test
cd gateway && go build ./... && go vet ./... && go test ./... -count=1
cd gateway && go test -race ./internal/session ./internal/autonomy ./internal/schedule
cd gateway/web && npm run check && npm test && npm run build
~~~

上面各行从仓库根目录独立执行。前端构建产物位于 gateway/internal/web/dist，前端改动后须一并更新；完整命令和可选端到端测试见 [README](../README.md#测试)。

Linux 单独验证内核可用 make -C kernel test NANO_TEST_NO_WINDOWS=1。Windows 观察器先构建 kernel/build/test_watch.exe，再复制到 Windows 本地新临时目录运行并记录输出和退出码；不要用“交叉编译成功”代替原生运行。macOS 本地缺环境时只记编译结论，原生结果以实际 runner 为准。

执行器与宿主测试的部分清理按进程特征匹配，不并行运行这两组脚本。端到端夹具使用临时数据目录，桌面夹具见 [桌面接入](COMPUTER-USE.md)。

## 容易破坏的边界

- 不在 App 总锁内等待模型、MCP、平台或其他外部 I/O。异步回调重新核验来源、版本和当前权限。
- 工具 schema 或稳定系统前缀变化时更新 prefixVer；动态时间、目录、经历和交接说明追加进消息。
- 模型配置只有 models.json 一个来源；全部删除后保持空状态，不重新导入旧 seed。模型 ID 可含斜杠，接口参数不要假设它适合直接拼路径。
- 工具“受理”“运行中”“转后台”和取消请求不是完成凭据。结果未知的发送、点击或命令先观察，不自动重放。
- silent 必须贯穿所有出口和派生任务，不能回退到 main、creator 或其他窗口。
- 分支列表不加载整段历史；迁移和校验用流式缓冲，不读入整份大历史。持久失败不能先回执成功。
- 旧布局只是备份。不要绕过激活、墓碑、世代和操作归属强行恢复，参见 [存储说明](STORAGE-v0.9.0.md)。
- 图片原始引用保留；模型不支持图片时给说明，不悄悄删除历史附件。

## 平台细节

- Windows 路径、参数和环境变量使用平台层 UTF-8/宽字符接口；不要把 ANSI getenv/argv 当 UTF-8。中文路径和带冒号会话 ID 都有回归。
- Windows 子进程树用 Job Object 管理；保持挂起创建、加入 Job、再恢复线程的顺序。
- ReadDirectoryChangesW 的缓冲区必须对齐；异步退订绑定原对象。watch 槽位不能因删除而移动，代际用于丢弃旧事件。
- WSL 共享路径覆盖可执行文件后可能运行到旧副本。每轮 Windows 专项复制到新本地目录，日志重定向到 Windows 文件，再确认退出码。
- C 日志截断须保持 UTF-8 边界，不用字节格式截断中文。
- macOS 构建需要对应平台宏和平台源文件；本机交叉编译不证明 GUI 权限、观察器或安装服务可运行。
- Windows 网关更新检查和安装识别可用，自动更新仍关闭；升级重跑新包安装脚本。

## 当前边界与发布

Linux 和 Windows 的 v0.9.0 功能范围已验收，Windows 观察器原生 12 项通过；macOS 原生验收按用户要求暂缓。版本验收摘要集中在运行时设计，后续只修改当前结论。

开发分支完成后按 [发布流程](RELEASE.md) 推送、检查 CI、合入 main、打标签。未经用户指示不强推、不改写已推送历史，不为补文档自动发布。
