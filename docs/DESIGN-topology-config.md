# 设计稿：拓扑图就是控制台（配置和节点合在一起）

状态：**已实现（v0.4，分支 dev/v0.4，2026-10-23）**
最后更新：2026-10-23
相关：[DESIGN-ui-interactions.md](DESIGN-ui-interactions.md)、[DESIGN-model-node.md](DESIGN-model-node.md)、[PLAN-roadmap.md](PLAN-roadmap.md)

## 为什么要改

用户原话：“我们目前既能用节点配置，又能在设置页面配置，我希望只保留一个，最好是基于拓扑节点配置……起码保证项目能够稳定运行，而不是到处漏风。”

v0.3.2 时的问题（逐项查过）：

- **两个入口**：设置页和节点面板各显示一部分，同一项有时两边都有、有时只有一边。
- **有的设置哪个节点都点不到**：模型请求参数（超时、温度、额外参数）只在设置页；默认权限模式只在“没有工作目录”时的占位节点上；`kernel` 组（监听地址、口令）挂在每一个内核节点上，点别的电脑的内核看到的却是网关自己的监听设置。
- **有的设置根本不在网关里**：每条消息最多请求模型几次（16）、最长多久（10 分钟）、等审批多久（5 分钟）、工具结果多长，写在每台电脑的 kernel.conf 里，网页改不了。（v0.3.3 已经改成网关的设置，每一轮带给内核。）
- **改了不生效**：“检查新版本”开关只在启动时读一次；检查更新不走代理设置。（v0.3.3 已修。）
- **管理页面分散**：设备、定时任务、人格各是一个页面，拓扑图上也有对应的节点，但节点里只能看、不能管。

## 原则

1. **拓扑图是唯一的控制台**。每个能配置的东西都是图上的一个节点；点节点就能看到它的全部状态、做全部操作、改全部设置。不再有设置页、设备页、定时任务页、人格页（旧链接自动跳到对应节点）。左侧只留“拓扑”和“会话”（聊天）。
2. **每个配置项只有一个家**。配置项的 `group` 就是它所在节点的名字，网关的测试保证每一项的 `group` 都是已知节点；网页按 `group` 渲染，万一有不认识的组，放到网关节点的“其他设置”里，绝不会丢。
3. **所有 agent 行为都由网关决定**。内核的 kernel.conf 只管连哪个网关（gateway、node、token、exec）。
4. **改完立即生效**，要重启的标“重启生效”，网关节点上显示待重启的数量和重启按钮。
5. **节点自己会说话**：有问题的节点（渠道报错、搜索开着没 key、没有模型、没有内核在线、待重启、有新版本、有电脑等配对）在图上直接带标记，不用点开才知道。

## 布局（从左到右）

| 列 | 节点 |
| --- | --- |
| 入口 | 网页、终端、Telegram、飞书、定时任务 |
| 会话 | 最近的会话（最多 9 个）、“全部会话” |
| Agent | Agent（现在只有一个，v0.5 起每个 agent 一个节点） |
| 网关 | 网关（中间的圆） |
| 能力 | 上下文与记忆、网络搜索、模型、技能；下面是内核 |
| 机器 | 本机、装了内核的电脑、SSH 服务器、“＋ 接入机器” |
| 工作目录 | 工作目录、“＋ 添加工作目录” |

列上方有淡色的列名。连线：入口 → 会话 → Agent → 网关 → 能力 / 内核 → 机器 → 工作目录。

## 每个节点管什么

| 节点 | 状态和操作 | 设置（group） |
| --- | --- | --- |
| 网关 | 版本、检查更新、更新、重启、运行时长、用量；改过的设置一览（可以一项项恢复） | `gateway`：默认代理（显示网关进程实际看到的代理）、更新、脱敏、内核连接、存储 |
| Agent | 人格（预览、编辑、套用预设，会话专属人格列表）、每条消息的上限 | `agent`：最多请求模型几次、最长多久、等审批多久、工具结果多长、默认权限模式、管理员、访客能用的工具、聊天窗口白名单、显示档位默认值、消息带时间、时区 |
| 网页 / 终端 / Telegram / 飞书 | 连接状态、聊过天的人（设管理员、接到主会话）、接入步骤、飞书扫码 | `web`：网页地址、登录密码；`cli`；`telegram`；`feishu`（各自的显示档位，默认“跟随 Agent”） |
| 定时任务 | 任务列表、新建 / 编辑 / 立即运行 / 暂停 / 删除、最近结果 | 每个任务自己的设置 |
| 会话 | 打开对话、窗口、工作目录、权限模式、模型、思考强度、人格、历史与归档、停止、重置、删除 | 每个会话自己的设置 |
| 上下文与记忆 | 整理过的会话、归档数 | `memory` |
| 网络搜索 | 今天的次数、key 从哪来、测试 | `search` |
| 模型 | 接口、模型、默认模型、测试（加宽面板） | `model`：请求超时、回传思考、默认温度、额外参数 |
| 技能 | 技能列表、目录 | `skills`：技能目录 |
| 内核 | 版本、系统、沙箱、工具、正在跑的会话、移除配对的电脑 | 无（行为由 Agent 决定，连接由机器决定） |
| 本机 | 本机内核、工作目录、浏览目录添加 | `local`：启动本机内核、本机内核的名字 |
| 别的电脑 / SSH 服务器 | 在线状态、沙箱、工作目录；SSH：连接、断开、编辑、删除 | 连接本身的设置 |
| ＋ 接入机器 | 等确认的配对请求（带确认码）、一行安装命令、添加 SSH 服务器 | `machines`：电脑接入地址 |
| 工作目录 | 路径、机器、默认挂载、在这里工作的会话、删除 | 无 |
| ＋ 添加工作目录 | 选机器、浏览目录 | 无 |

## 操作逻辑

- **左键**节点：右边打开它的面板。面板从上到下固定是：状态 → 操作按钮 → 设置（按小节，高级的折叠） → 危险操作（删除、移除）。
- **右键**节点：常用操作（和面板里的操作按钮一样），第一项是“查看和设置”。
- **双击**会话：打开对话。
- **“＋”节点**：添加东西的固定入口，不用记右键菜单。
- **搜索**：顶栏的搜索框和画布右下角的「搜索设置」（⌘K / Ctrl+K），搜设置项、节点、会话、操作；选中设置项就打开它所在的节点并高亮那一项。
- 面板宽度：普通 440；模型、人格编辑、定时任务、接入机器用加宽面板。面板左边缘可以拖动调宽度，记在浏览器里。
- 旧链接：`#/settings?focus=键` 打开那一项所在的节点；`#/devices` 打开“接入机器”；`#/schedules` 打开定时任务；`#/personas/文件` 打开 Agent 的人格编辑。

## 保证不漏

- Go 测试：每个配置项的 `group` 都在已知节点列表里；每个已知节点都有至少一项或者明确标为“没有全局设置”。
- 网页：渲染时按 `group` 取设置项；不认识的组放进网关节点的“其他设置”。
- 浏览器检查（`make test-ui`，本机跑，用临时数据和假模型）：逐个点开所有节点，确认每个配置项恰好出现在一个节点里；改一个数字项、一个开关、一个文本项，刷新后还在；旧链接跳对地方；整个过程没有 JS 报错。
- 发布前除了 `make test`，再跑一次 `make test-ui`。
