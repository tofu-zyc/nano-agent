# 长时间命令和后台任务

Shell 的前台等待与真正执行的 Job 分开。转后台只移交等待关系，不重新执行命令；
后台任务继续占执行槽及资源锁。`queued` 只是排队，`backgrounded` 只是已经移交，
`unknown` 表示不能确认原进程结果，都不能当作成功。

## 工具和文字命令

- `Job` 工具：`list / status / output / wait / cancel / detach`。
- `/jobs`：查看当前权限可见的任务。
- `/stop all`：停止当前前台 run，并取消本人在此会话发起的所有活动 Job；管理员也不会扩大这个“本人”范围。
- `/bg`：把当前会话唯一的前台任务原地转后台；有多个时需 `/bg <job_id>`。
- `/job <job_id>`：查看持久状态；节点离线时仍可查看。
- `/job <job_id> output [游标]`（也可用 `logs`）：读取有界日志并显示下次游标。日志可能为二进制；
  工具/API 保留 base64 原始块，文字命令把不可显示字节转换为替代符。
- `/job <job_id> wait [秒]`：最多 10 秒，完成事件直接唤醒，不调用模型轮询。
- `/job <job_id> cancel` 或 `/stop <job_id>`：请求停止同一条真实执行。
- `/job <job_id> detach` 与 `/bg <job_id>` 等价。

这些命令直接处理，不排在聊天消息或模型后面。`/stop all` 最多 16 组同时处理、每组 4 个请求，重复命令合并；它报告取消受理数量与未确认数量，不把受理当成退出。
异步日志/命令/按钮回复共用原渠道与 agent 范围校验，渠道替换或改绑不能把旧操作结果转发给新来源。短等待或日志查询被取消只移除查询，
不会取消实际任务。取消/转后台请求超时时，操作可能仍在保存；查询原任务核实，
不要为同一命令换 ID 或重新运行。取消回执表示受理，最终以原 Job 的终态为准。

状态和日志沿固定 agent、创建者、来源会话和 silent 范围检查；当前 agent 切换不会取得
其他 agent 的任务。安静分支只操作自己来源的 Job，后台完成不借 main/creator 回退投递。
网页管理员的全局查看由统一控制入口检查。权限被限制为只读时不能移交后台所有权。

只有 `status/wait` 返回实际 `succeeded` 的任务可作为完成凭据；
日志读取、排队、运行中、未知结果、取消受理不能冒充完成。
读取状态、日志与短等待不会新增 Schedule。

## 长调用提示和平台按钮

实际开始执行后满 `runtime.long_call_hint_seconds`（默认 10 秒，1–3600），
前台命令只提示一次；排队时间不计入。提示不受“简洁/过程/详细”档位影响。
飞书与 Telegram 显示“转入后台 / 查看输出 / 停止命令”，其他渠道显示对应文字命令。
执行状态来自已保存的 Job 回执；按钮受理不表示进程已经停止或移交已经完成。

每个按钮携带 26 字节的不透明令牌，在 Gateway 端绑定原 agent、节点、Job、来源会话、
原卡片消息、渠道对象及允许动作。点击重新核验当前权限，窗口切换不会改变原任务，
机器人换绑、渠道替换、撤权、过期或不匹配的消息不能取得新的执行权限。
相同操作进行中合并；已受理的取消/移交不会因重复点击再次提交。
令牌有效 24 小时，Gateway 重启后失效；持久任务继续通过命令或网页操作。

Telegram 先调用 `answerCallbackQuery`，再提交任务控制；
飞书回调只返回“已收到，正在核验”，经现有队列交给 Gateway。
卡片由持久状态的普通消息投影接口刷新，终态移除取消/移交按钮，
不使用回调 Card 返回值来抢先宣告完成。
平台请求复用有界发送队列，不占 App 总锁；更新合并限频，最多重试 3 次。
首次发送超时不盲目重发卡片，保留文字命令入口。silent Job 不产生这些提示或卡片。

提示跟踪最多 1024 个，卡片最多 256 张、每张最多 3 个令牌；
结束后保留 30 分钟，过期或失效来源回收，不复制命令日志进卡片缓存。
平台格式与 callback 用模拟 API 验证；真实飞书/Telegram 账号及权限尚未实测。

## 网页

顶栏的“执行任务”和搜索里的同名入口可在当前聊天旁打开面板，保留正在查看的会话。
任务列表分页加载元信息；点击任务可查询状态、继续读取游标日志、短等最多 10 秒、
取消或原地转后台。日志按需读取，页面保留最多 128K 字符；缺口有明确提示。
实时状态更新不会主动切换窗口或为 silent Job 生成聊天通知。

直接链接为 `#/jobs/<job_id>?node=<节点名>`（编号与节点需 URL 编码）。
接口为 `GET /api/jobs?node=&after=&limit=` 和
`POST /api/jobs/{job_id}/control`；后者接收统一 JobRequest，动作、身份和权限
与工具、命令完全相同。需要网页登录，改动请求携带 `X-Nano: 1`。
SSE 的 `job` 事件只携带 JobInfo 元信息，不发送原始命令、资源锁、结果正文或日志尾部。
节点离线仍保留可查询状态；日志和执行控制明确返回节点不可用。

## 能力和限额

协调内核须声明 `job_control_tool=1`，Gateway 才向模型提供 Job 工具；
旧内核继续原有工具范围。后台执行另需完整的
`job_stream + machine_leases + lease_detach + job_manager` 链路，不能仅因支持查询而启动后台命令。
当前生产 App 的后台能力协商尚未开放，待网页与平台入口接齐后启用；真实 C/Go 测试夹具已使用完整链路。

控制和短等待各最多 128 个；单次日志最多 64 KiB，默认 8 KiB，游标为绝对原始字节位置。
列表分页最多 100 条，只复制元信息，不复制结果正文、日志尾部及完整资源域。
日志轮转或写入丢失返回缺口标记，不能将片段当成完整审计记录。

节点重连先核对完整租约和 Job 固定身份。节点重启不重放保存的命令：
未启动任务恢复 interrupted，不能确定进程结果的恢复 unknown，并保留资源占用。
来源或存储恢复失败会显示诊断，未提交副本不作为可执行任务激活。

## 验证

Go race 覆盖实际权限、分页、控制关联、查询取消、短等待缓存回收、来源事件唤醒、
命令绕过模型队列及任务凭据。真实 C/Go 测试用模型替身跑通 Shell→Job→会话结束→取消/等待；
Linux ASan 和原生 Windows 节点验证原地移交、同 PID、单次调用结果、二进制游标、
重连/重启、silent 来源与 Job 工具到 Gateway 的路由。


网页回归使用真实 HTTP→Hub→节点 NDJSON 往返验证 output/detach/cancel、
可靠终态 ACK 与 SSE 投影，并从磁盘重建初始索引；覆盖登录/请求保护、
离线、严格参数与分页。网页语义测试覆盖同名不同节点、迟到回执和跨页 UTF-8。


长调用专项以真实 C 模型循环运行 foreground Shell，模拟时钟触发提示后点击转后台按钮：
原 run 结束、原进程 PID 不变、命令只启动一次、最终完成回执保存。
浏览器回归覆盖实际控件、日志跨页中文与表情、迟到 HTTP 不覆盖终态、
silent 更新不改主聊天或全局通知，以及直接链接；截图在 build/ui-check/jobs.png。

模型的 Job 日志视图遵守现有脱敏配置：在同一有界页内先合并二进制分片再脱敏，
避免 base64 及跨分片密钥绕过纯文本匹配；保持原游标跨度并标记 redacted。
原始审计历史、用户日志接口与 security.redact=off 行为保留。
回归先复现旧实现的编码密钥漏出，再验证模型请求、私钥、游标跨度和原始历史。
