# 设计稿：模型管理回到拓扑节点

状态：**设计已确认（迁移方式 1），按第 8 节实施**  
最后更新：2026-10-22  
相关：[HANDOFF.md](HANDOFF.md)、[ARCHITECTURE.md](ARCHITECTURE.md)

## 0. 先纠正概念

**模型就是模型。** 一个模型 = 某个接口上的一个模型名。模型只有一个来源：模型列表（`data/models.json`）。

- **没有“配置文件模型”这个东西。** `gateway.toml` 的 `[llm]` 不再定义模型。
- **没有模型等级/层级。** 列表里按接口分组只是分组，不是高低；唯一的标记是“默认模型”（新会话用哪个），随时可换。
- **没有模型就是没有。** 不自动建模型、不隐式回退、不拿配置文件凑一个。界面显示空状态，引导用户添加接口和模型；聊天里明确提示“先配置模型”。
- **接口和模型都可以改、可以删。** 删掉默认模型就落到下一个可用模型；全删光就回到空状态。

`[llm]` 以后只保留**和具体模型无关的全局默认**：请求超时、默认温度、额外请求参数、回传思考、裁剪比例、默认上下文/历史上限等。接口地址、密钥、模型名、输入类型这些都只属于模型列表里的接口/模型。

### 0.1 旧概念是怎么来的

早期网关只支持一个模型，写在 `gateway.toml` 的 `[llm]` 里。后来加了多模型（`models.json` + 网页管理），旧配置被保留成一个特殊端点 `config`，界面上叫“配置文件模型”。结果是用户看到两个来源、两种“模型”，不知道在配哪个。这是实现细节泄漏，删掉。

处理方式：**一次性迁移**。升级后第一次启动，把旧 `[llm]` 里的模型导入成模型列表里的一个**普通接口 + 普通模型**（列表里已有模型就保留原来的默认模型），并写入 `seeded` 标记；之后不再导入。它和别的模型完全一样，可以改、可以删；删了重启也不会复活。

新装用户（示例配置里已经没有 `[llm].model`）第一次打开就是空状态，自己加。

## 2. 交互总原则

1. **一个对象只有一个地方配置。** 模型和接口都在模型节点面板里。
2. **画布是唯一操作台。** 左键点节点 = 查看/配置；右键点节点 = 对该节点的操作；右键空白 = 新建。
3. **不跳页。** 面板是画布的延伸；⌘K 的动作也落到画布面板。
4. **破坏性操作二次确认，并写清影响。**
5. **所有异步操作有反馈**：忙碌态、成功 toast、失败原因。
6. **键盘可用**：Esc 关闭菜单/面板；Tab 能走完表单。
7. **面板宽度按内容分级**：普通 430px；模型 760px；窄屏单列。

| --- | --- |
| 网关 | 网关面板 |
| 渠道 | 渠道面板 |
| 会话 | 会话面板 |
| **模型** | **模型面板（加宽：左侧接口/模型列表，右侧详情）** |
| 内核 | 内核面板 |
| 机器 / SSH | 机器面板 |
| 工作目录 | 工作目录面板 |

### 3.2 右键节点

| 节点 | 菜单项（本次新增加粗） |
| --- | --- |
| **模型** | 查看和设置；**添加模型**；**添加接口**；**测试默认模型**；分隔线；全部设置（跳到设置页的“上下文与采样”） |
| 会话 | 打开对话、挂载/取下工作目录、查看和设置、停止当前任务、清空上下文、删除会话（main 不可删） |
| 工作目录 | 挂到主会话/取下、设为新会话默认、查看和设置、从列表里删掉 |
| 机器 / SSH | 浏览目录添加工作目录、查看和设置、连接/断开、在设备页管理 |

### 3.3 右键画布空白

| 菜单项 | 行为 |
| --- | --- |
| **新增接口（模型服务）** | 打开拓扑 + 模型面板，右侧直接显示“添加接口”表单；保存后自动接着添加模型 |
| **新增工作目录…** | 打开现有的“选择机器 → 浏览目录”流程；成功后工作目录节点出现在画布上 |
| **接入电脑 / SSH 服务器…** | 打开现有的设备页流程（配对/SSH 需要二维码或较长表单，属于合理例外） |
| 分隔线 | |
| 适应窗口 | 等价于右下角按钮 |

暂不做：右键空白“新建会话”。

### 3.4 删除与空状态

| 对象 | 能否删除 | 影响 |
| --- | --- | --- |
| 模型 | 能 | 单独选了它的会话改回默认模型 |
| 接口 | 能 | 它上面的模型一起删掉；机器上的服务不受影响；会话改回默认模型 |
| 模型节点本身 | 不能删 | 固定节点 |

- 删掉默认模型：落到下一个可用模型；没有可用模型就进入空状态。
- 空状态：模型节点显示“还没有模型”；模型面板显示“添加接口 → 添加模型”；聊天输入区提示“先配置模型”，不发起请求。
- 不再有“配置文件模型不能删”这种特例。

## 4. 模型节点面板

### 4.1 节点上的样子

- 第一行：`模型 · 2 个接口`（没有接口时 `模型 · 还没有配置`）。
- 第二行：默认模型的显示名（没有模型时显示“还没有模型”）。
- 第三行：默认模型所在的接口名和地址；默认模型支持图片时加“图片”标签。
- 打开面板时节点高亮。
- **不显示“配置文件”“内置”“等级”之类的标签。**

### 4.2 打开方式

- 左键点模型节点。
- 右键模型节点 → 查看和设置 / 添加模型 / 添加接口 / 测试默认模型。
- 顶栏模型胶囊：回到拓扑并打开模型面板；没有模型时胶囊显示“未配置模型”，点击同样打开面板。
- ⌘K：搜“添加模型”“测试模型连接”，打开拓扑面板并直接进对应表单。

### 4.4 左侧列表

- 顶部：默认模型摘要 + 接口数 + 模型数；右侧 **+ 模型**、**+ 接口**。
- 搜索：模型名、显示名、接口名、接口地址。
- 接口按创建顺序分组；没有特殊顺序、没有“配置文件优先”。
  - 接口头：名字、类型标签（openai/mock）；右侧编辑图标。
  - 模型行：默认圆点、显示名、模型名；标签只有“默认”和“图片”。
  - 点模型行 → 右侧详情；点接口头/齿轮 → 右侧接口编辑。
  - 接口下没有模型：显示“这个接口还没有模型” + 添加模型链接。
- 没有任何模型：显示空状态“还没有模型，先添加一个接口”，主按钮“添加接口”。

### 4.5 右侧详情

#### 头部

- 显示名、模型名、所属接口；标签只有“默认”“图片”。
- 操作：**设为默认**（已是默认则隐藏）、**测试连接**、**删除模型**。
- 测试结果在头部下方：通了显示首字/总耗时和回复；失败显示原因。

#### 接口分区

- 所有接口统一：名字、类型（openai/mock）、接口地址、API Key（留空表示不改）、代理。
- 没有“配置文件接口”这种特例；谁都可以改，也可以删。
- 请求超时是全局设置，不放在接口里。

#### 模型分区

- 模型名（接口里的真实名字）、显示名（网页/`/model` 显示，留空用模型名）。
- 上下文窗口（必填，创建时预填 131072）、最大输出（可选）、历史上限（留空按上下文窗口一半）。
- 默认思考强度、可选思考强度。
- 输入类型：`文字` 固定；`图片` 可勾选。
- 新建模型时可选“从接口读取模型列表”，自动填模型名、上下文窗口，接口报 `image` 时自动勾图片。

#### 保存

- 显式“保存”；保存中禁用；成功 toast 并刷新列表/顶栏。
- 所有模型统一写 `data/models.json`，没有第二套存储。

### 4.6 添加流程

1. **添加接口**：名字、类型、地址、Key、代理 → 保存 → 自动接着打开“添加模型”（接口已选好）。
2. **添加模型**：没有接口时先走 1；有接口时选接口 → 填模型 → 保存。
3. 右键模型节点/画布空白“新增接口”走同一套流程。

### 4.7 默认模型

- 默认模型只决定：新会话、没有单独选模型的会话用哪个。
- 随时可以改；不是等级，不影响模型能力。
- 删除默认模型：落到下一个可用模型；没有模型就空状态。

### 4.8 未保存、加载、错误

- 有改动时保存按钮旁显示“未保存”；切换模型/接口/节点或 Esc 关闭时确认“放弃未保存的修改？”。
- 加载中显示“正在读取模型…”；读取失败显示错误和“重试”。
- 保存失败保留输入并在表单上方显示原因。

## 7. 数据、接口与迁移

### 7.1 唯一模型来源

- `data/models.json` 是唯一的模型/接口列表；`GET /api/models` 只返回里面的内容。
- 不再从 `[llm]` 合成 `config` 端点/模型；不再有 `config: true` 这种特殊标记。
- 删除 `PUT /api/models/config`（为旧概念写的接口）。
- 接口不再单独存 `timeout`；请求超时是全局设置。

### 7.2 `[llm]` 以后管什么

只保留和具体模型无关的全局项：

- `llm.timeout`：请求超时
- `llm.temperature`：默认温度
- `llm.extra`：额外请求参数
- `llm.send_reasoning`：回传思考
- `llm.trim_to`：裁剪比例

`llm.provider/base_url/api_key/model/modalities/proxy/thinking/thinking_levels/context_window/max_tokens/max_history_tokens` 这些**不再作为模型配置**；新装用户不需要写，老用户只在迁移时读一次。

### 7.3 一次性迁移

`models.json` 增加 `"seeded": true` 标记。网关启动时：

1. 如果 `seeded` 为真：什么也不做。
2. 如果 `seeded` 为假：
   - 把旧 `[llm]` 里的模型导入成普通接口 + 普通模型：
     - 接口 ID 仍用 `config`（只为兼容已有会话的 `config/模型名` 引用；界面不显示这个 ID，也没有任何特殊行为）。
     - 接口名字用地址里的主机名（比如 `10.111.138.180`、`api.deepseek.com`）；mock 用“假模型”。
     - 模型名字、上下文窗口、最大输出、历史、思考强度、输入类型从 `[llm]` 复制。
     - 如果模型列表里已经有模型，仍然导入它，但保留原来的默认模型；如果列表是空的，把它设为默认。
   - 写 `seeded: true`。
3. 如果 `[llm].model` 为空且不是 mock：不导入模型，只写 `seeded: true`，界面进入空状态。

迁移后的模型和别的模型完全一样：

- 可以改、可以删、可以换默认；
- 删了重启不会复活（`seeded` 已为真）；
- 会话设置里原来指向 `config/模型名` 的，继续有效；如果模型被删，按现有规则回退默认。

新装：示例配置不再写 `[llm]` 的模型字段，第一次启动就是空状态，由用户自己添加。

### 7.4 没有模型时网关的行为

- 网关正常启动，网页/终端/渠道都能进。
- 聊天消息不进入 run；直接回复或提示“还没有配置模型，请先在网页的模型节点里添加接口和模型”。
- 网页聊天输入区显示提示和“去配置模型”按钮。
- `/model`、顶栏胶囊、模型节点都指向空状态。
- 不给任何“隐式 mock 模型”之类的兜底。

### 7.5 会话和默认模型

- 会话单独选模型、历史、上下文压缩逻辑不变。
- 默认模型只存在 `models.json` 里；没有“配置文件默认”这一层。
- 删除模型/接口时，`ModelsChanged` 把指向已删模型的会话改回默认；没有默认则进入空状态。
