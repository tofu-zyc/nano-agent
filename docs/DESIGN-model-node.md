# 设计稿：模型配置回到拓扑节点

状态：**设计稿，先评审，不动代码**  
最后更新：2026-10-22  
相关：[HANDOFF.md](HANDOFF.md)、[ARCHITECTURE.md](ARCHITECTURE.md)

## 1. 为什么要重做

现在模型配置有三套入口，互相重叠，用户不知道自己在配哪个模型：

1. **设置 → 模型**：把 `[llm]` 的 16 个字段平铺出来。没有模型列表，没有“当前在改谁”，模型名只是其中一个输入框。
2. **拓扑 → 模型节点**：右侧 430px 检查器里，上面是模型列表面板，下面又是同一批 `[llm]` 字段。重复、拥挤、层级混乱。
3. **曾经尝试的独立「模型」页面**：列表 + 详情本身是对的，但它违背了“拓扑就是操作台”——多一次导航、多一个页面记忆点，和节点割裂。**这个方向撤掉，不做独立页面。**

同时，画布的节点交互不完整：

- 右键画布空白处没有菜单（弹的是浏览器菜单）。
- 右键模型节点只有“查看和设置”，加模型/加接口的入口在面板深处。
- 删除会话、删除工作目录已经藏在右键里，但没有形成统一的“右键 = 操作”的规则。

结论：

- **模型相关的一切只在模型节点里完成**，节点面板加宽，左边模型列表、右边详情。
- **画布是唯一操作台**：左键点节点 = 查看/配置；右键点节点 = 对该节点的操作；右键空白 = 新建。
- **设置页不再出现模型/接口字段**，只保留全局的上下文、采样等默认值。

## 2. 交互总原则

1. **一个对象只有一个地方配置。** 模型和接口都在模型节点面板里；设置页不再重复。
2. **节点 = 实体。** 鼠标左键选中并打开右侧面板；右键弹出动作菜单；动作菜单里的“查看和设置”与左键一致。
3. **不跳页。** 面板是画布的延伸，打开/关闭不改变当前页面；面板里的操作不把用户带到别的页面。
4. **破坏性操作必须二次确认，并写清楚影响。** 例如“删掉接口，它上面的 3 个模型也会删掉；机器上的服务不受影响”。
5. **所有异步操作都有反馈。** 保存/测试/删除时按钮进入忙碌态；成功后 toast；失败在表单里显示原因。
6. **键盘可用。** Esc 关闭菜单/面板；Tab 能走完表单；⌘K 的动作最终也落到画布面板，不产生新页面。
7. **面板宽度按内容分级。** 普通节点 430px；模型节点 760px（列表 + 详情）；窄屏自动退化为单列。

## 3. 画布：左键、右键、空白

### 3.1 左键

| 节点 | 左键行为 |
| --- | --- |
| 网关 | 打开网关面板（状态、访问控制、网页设置） |
| 渠道（网页/Telegram/飞书/命令行） | 打开渠道面板（状态、配置） |
| 会话 | 打开会话面板（设置、模型、工作目录、删除） |
| **模型** | **打开模型面板（加宽，左侧接口/模型列表 + 右侧详情）** |
| 内核 | 打开内核面板 |
| 机器 / SSH 服务器 | 打开机器面板 |
| 工作目录 | 打开工作目录面板 |

### 3.2 右键节点

通用菜单第一项都是“查看和设置”，与左键一致。

| 节点 | 菜单项（本次新增加粗） |
| --- | --- |
| **模型** | 查看和设置；**添加模型**；**添加接口**；**测试默认模型**；分隔线；全部设置（跳到设置页的“上下文与采样”） |
| 会话 | 打开对话、挂载/取下工作目录、查看和设置、停止当前任务、清空上下文、删除会话（main 不可删） |
| 工作目录 | 挂到主会话/取下、设为新会话默认、查看和设置、从列表里删掉 |
| 机器 / SSH | 浏览目录添加工作目录、查看和设置、连接/断开、在设备页管理 |
| 内核 | 查看和设置、它所在的机器、移除这台电脑 |
| 渠道 | 查看和设置、启用/停用 |
| 网关 | 查看和设置、全部设置 |

模型节点的“添加模型/添加接口”不是新开页面，而是打开模型面板并直接进入对应表单。

### 3.3 右键画布空白

新增一个“新建”菜单：

| 菜单项 | 行为 |
| --- | --- |
| **新增接口（模型服务）** | 打开拓扑 + 模型面板，右侧直接显示“添加接口”表单；保存后自动接着给这个接口添加模型（和现有流程一致） |
| **新增工作目录…** | 打开现有的“选择机器 → 浏览目录”流程；添加成功后工作目录节点出现在画布上 |
| **接入电脑 / SSH 服务器…** | 打开现有的设备页流程（配对/SSH 需要二维码或较长表单，属于合理例外） |
| 分隔线 | |
| 适应窗口 | 等价于右下角的“适应窗口”按钮 |

暂不做：右键空白“新建会话”。会话是聊出来的，新建入口在会话页和 ⌘K；以后需要再加。

### 3.4 删除语义

| 对象 | 能否删除 | 影响 |
| --- | --- | --- |
| 模型（网页里加的） | 能 | 单独选了它的会话改回默认模型 |
| 接口（网页里加的） | 能 | 它上面的模型一起删掉；机器上的服务不受影响；会话改回默认模型 |
| 配置文件里的模型 | **不能删** | 只能改；模型名改成空的会被拒绝（openai 模式） |
| 配置文件里的接口 | **不能删** | 只能改；在面板里编辑 |
| 模型节点本身 | 不能删 | 它是固定节点 |

## 4. 模型节点面板（核心）

### 4.0 节点上的样子

模型节点保持现在的位置和卡片样式，只调整信息层级：

- 第一行：`模型 · openai`（接口类型），有多个接口时显示接口数。
- 第二行：默认模型的显示名（没有模型时显示“未配置”）。
- 第三行：默认模型的关键信息（接口地址、思考强度），默认模型支持图片时加一个“图片”小标签。
- 打开面板时节点高亮，和右侧面板对应。

### 4.1 打开方式

- 左键点模型节点。
- 右键模型节点 → 查看和设置 / 添加模型 / 添加接口。
- 顶栏模型胶囊：跳到拓扑并打开模型面板（不是新页面）。
- ⌘K：搜“添加模型”“测试模型连接”，打开拓扑并直接进入对应表单。

### 4.2 布局

面板宽度 760px（普通面板 430px）；窄屏（<1000px）退化为单列，列表和详情之间用“返回列表”切换。

```
┌ 模型 ─────────────────────────────────────────────────────────── × ┐

│ ┌ 接口 / 模型 ─────────────┬ 详情 ──────────────────────────────┐ │
│ │ 搜索模型或接口…           │ deepseek-v4.1-flash  默认  支持图片   │ │
│ │                          │ config/deepseek-v4.1-flash           │ │
│ │ ▸ 配置文件   [配置文件]    │ [设为默认] [测试连接] [删除模型]        │ │

│ │   ○ qwen-vl  图片         │ └──────────────────────────────────┘ │ │
```

### 4.3 左侧：接口 / 模型列表

- 顶部：当前默认模型摘要 + 模型数 + 接口数；右侧两个按钮：**+ 模型**、**+ 接口**。
- 搜索框：同时过滤模型名、显示名、接口名、接口地址。
- 接口分组，顺序：配置文件（`config`）永远第一，其余按创建顺序。
  - 接口头：名称、类型标签（openai/mock）、配置文件标签；网页接口右侧有编辑图标。
  - 模型行：默认圆点、显示名、模型 ID；右侧标签（默认/图片）。
  - 点击模型行 → 右侧详情。
  - 点击网页接口名/齿轮 → 右侧进入接口编辑；点击配置文件接口 → 选中它的模型（接口字段在模型详情的“接口”分区里）。
  - 接口下没有模型：显示“这个接口还没有模型”，并给“添加模型”链接。
- 默认模型在列表中高亮并标“默认”。
- 没有网页接口时，点 **+ 模型** 会先打开“添加接口”表单，保存后自动接着打开“添加模型”（接口已选好），不会出现没接口可选的死路。
- 空状态：没有任何模型时，列表显示“添加一个接口，再给它加模型”，主按钮指向添加接口。

### 4.4 右侧：详情

#### 头部

- 显示名 / 模型 ID / 接口名 / 标签（默认、配置文件、支持图片）。
- 操作按钮：**设为默认**（已是默认则隐藏）、**测试连接**、**删除模型**（配置文件模型不显示）。
- 测试结果就显示在头部下方：通了显示首字/总耗时和一句回复；失败显示原因。

#### 表单分区

**1）接口**

| 情况 | 显示 |
| --- | --- |
| 配置文件模型 | 提示“这是 gateway.toml 的 `[llm]`，修改写到 `data/config.json` 覆盖层，不改原文件，下一条消息生效”；字段：接口类型、接口地址、API Key、代理、请求超时 |
| 网页模型 | 只读显示接口名和地址，右侧“编辑接口”按钮；编辑接口切到接口表单 |
| 新建模型 | 接口下拉（网页接口）+“新建接口”链接 |

**2）模型**

- 模型名（接口里的真实名字）、显示名（网页/`/model` 显示，留空用模型名）。
- 上下文窗口、最大输出、历史上限（留空按窗口一半）。
- 默认思考强度、可选的思考强度。
- 输入类型：`文字` 固定选中不可取消；`图片` 可勾选。旁边说明“纯文字模型收到图片时只会看到一句说明”。
- 新建网页模型时，顶部有“从接口读取模型列表”，选中自动填模型名、上下文窗口，并在接口报 `image` 时自动勾图片。

**3）保存**

- 显式“保存”按钮；保存中禁用。
- 配置文件模型保存后写覆盖层；网页模型保存后写 `data/models.json`。
- 保存成功：列表刷新、详情保持选中、`store.reloadModels()` 让顶栏/会话选择同步；toast“模型已保存”。

#### 接口表单

- 字段：名称、类型（openai/mock）、接口地址、API Key（留空表示不改）、代理。
- 配置文件接口不可从这里编辑，入口在配置文件模型的“接口”分区。
- 保存后：如果是从“添加模型”引导来的，自动接着打开“添加模型”（接口已选好）；否则回到该接口。
- 删除接口：确认文案包含“它上面的 N 个模型也会删掉；机器上的服务不受影响”。

### 4.5 默认模型

- 默认模型决定：新会话、没有单独选模型的会话。
- 设为默认后列表和顶栏胶囊立即更新。
- 删掉默认模型时，按现有 `models.Store.Default()` 规则落到下一个可用模型；如果配置文件模型存在，通常是它。

### 4.6 配置文件的模型

- 在列表里是普通一行，标签“配置文件”，但不可删除。
- 它的接口字段和模型字段全部映射到 `[llm]`（通过 `data/config.json` 覆盖层写入）：
  - 接口：`llm.provider`、`llm.base_url`、`llm.api_key`、`llm.proxy`、`llm.timeout`
  - 模型：`llm.model`、`llm.context_window`、`llm.max_tokens`、`llm.max_history_tokens`、`llm.thinking`、`llm.thinking_levels`、`llm.modalities`
- 这些值同时是网页模型的默认值（网页模型留空的项沿用 `[llm]`），在表单帮助文字里说明。
- API Key 只显示“已设置/未设置”，不回传明文；留空表示不改。

### 4.7 未保存修改

- 表单有改动时，保存按钮旁显示“未保存”。
- 切换模型/接口/节点前如果有未保存修改，弹确认“放弃未保存的修改？”。
- Esc 关闭面板同样走这个确认。

### 4.8 加载、错误、空状态

- 打开面板先显示加载骨架/“正在读取模型…”。
- 读取失败：面板里显示错误和“重试”。
- 保存失败：表单上方红色错误框，保留用户输入。
- 测试失败不影响保存。

## 5. 设置页的调整

- **删掉“模型”分组**（`llm.provider/base_url/api_key/model/modalities/proxy/timeout/thinking/thinking_levels/context_window/max_history_tokens/max_tokens`），这些只出现在模型节点面板。
- **新增“上下文与采样”分组**：`llm.temperature`、`llm.extra`、`llm.send_reasoning`、`llm.trim_to`。这些是给所有模型的全局默认/行为，不针对某一个模型，留在设置里不冲突。
- 设置页不再出现“模型面板/添加模型”的提示卡片；模型入口就是画布节点。
- 设置页不再有这些字段；⌘K 搜到“模型 / 接口 / API Key / 多模态”时打开模型节点面板（见 6.3），不再落在设置页。
