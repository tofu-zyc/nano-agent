# 架构

nano-agent 由两部分组成：**网关**是唯一有状态的中心，资源充足；**内核**是 agent 本身，无状态，资源受限。

```
            聊天平台 / 网页 / 终端
                     │
              ┌──────┴───────┐        SSH（网关自己连）
              │     网关      │ ─────────────────────────▶  SSH 服务器（不跑内核，按次运行执行器）
              │ 会话 · 上下文 │
              │ 模型 · 工作目录│ ──▶ 本机执行器（网关所在的机器）
              └──┬────────┬──┘
        内核协议 │        │ 内核协议
           ┌─────┴──┐  ┌──┴─────┐
           │ 内核 A │  │ 内核 B │      装在任何设备上（WSL、别的电脑、手机）
           │ 执行器 │  │ 执行器 │      同机的工作目录由自己的执行器执行
           └────────┘  └────────┘
```

## 角色

**网关**
- 会话、上下文、模型调用、聊天平台、网页。
- **机器**：能放工作目录的地方，有三种：
  - **本机**：网关所在的机器。网关自己启动一个本机内核（`gateway`，退出了自动重启），自己也能运行执行器 `nano-exec`。
  - **SSH 服务器**：在网页拓扑图「＋ 接入机器」节点里添加（地址、端口、用户、密码，或 `~/.ssh/config` 的别名）。网关自己连（复用连接），自动把执行器传上去，跑不了就在服务器上现编，断了自动重连。服务器上不常驻任何进程，每次调用工具就运行一次执行器。
  - **装了内核的电脑**：内核连上网关，它所在的机器就出现在机器列表里。
- **工作目录**：机器 + 路径（`本机:/mnt/d/Agent-Workspace`、`gpu-server:~/proj`）。网关维护工作目录列表，拓扑里挂在各自的机器下。每个会话从列表里挂任意几个（可以在不同的机器上，一个都不挂就是只读），标了默认的新会话自动挂上。
- **模型**：接口和模型只存在数据目录的 `models.json`，在网页拓扑的模型节点里管理；没有模型时就是空状态，聊天会提示先添加接口和模型，不会自动造模型。旧版 `[llm]` 的单模型在升级后第一次启动时一次性迁移成普通模型（`seeded` 标记防止复活），`[llm]` 之后只保留超时、温度等全局默认。新会话、没单独选模型的会话用默认模型，每个会话也可以单独选（`/model`、会话设置）。每个模型有输入类型（text / image），决定用户发的图片发不发给它。
- **图片**：用户发来的图片存在数据目录的 `uploads`（按内容哈希去重），历史里只存引用；发给支持图片的模型时做成 OpenAI 的 content parts。
- **技能**：放在网关上（`skills/`），所有内核共用。`Skill` 由网关处理，附带文件按需放到执行工具的机器的 `~/.nano-agent/skills/`。

**内核**
- 对话循环：要模型回复 → 拿到工具调用 → 按权限模式决定直接执行、等审批还是拒绝 → 执行 → 汇总结果 → 下一轮；预算、超时、审批等待。
- 自带执行器，能在**自己所在的机器**上执行工具（沙箱：Landlock + seccomp）。
- 不连 SSH、不上传、不编译。安装脚本在任何 Linux / WSL 设备上把它装好、设成开机启动；连网关时填地址，别的设备第一次连上来要在网页里核对确认码（配对）。

## 两种执行模式

每一轮开始时，网关挑跑这一轮的内核：第一个挂载的工作目录那台机器上有内核就用它，其次是别的挂载的机器上的，再其次本机的、最近连上来的。然后**每个工具调用**按参数 `workspace` 指的工作目录分两种：

| | 条件 | 工具在哪执行 |
|---|---|---|
| **同机** | 工作目录就在这个内核的机器上 | 内核自己的执行器，在本地执行 |
| **异机** | 工作目录在别的机器上 | 内核把调用交给网关（`exec`）。网关在那台机器上执行：本机直接运行执行器，SSH 服务器走 SSH，装了内核的电脑请它的内核代为执行（`run`）。结果交回内核 |

- 本机的内核掉线时，别的设备上的内核顶上，本机和 SSH 服务器上的工作目录**照样能用工具**。
- 挂载的工作目录所在的机器不在线：这一轮不挂它，告诉模型；全都用不了就只读（管理员 Read/Grep，不能写和执行）。
- 异机时，执行的约束（工作目录、只读、能不能写）由**网关**按会话的设置生成，不信任内核传来的路径。管理员额外拿到 `ro: ["/"]`（能读整台机器，写仍只在工作目录）；访客仍然只能读工作目录和技能缓存。
- 同一台机器上挂的几个工作目录在沙箱里互相都能读写（`dirs` 一起给），方便在它们之间拷文件。

## 协议要点

- 网关 → 内核 `input` 带 `workspaces[{name, dirs, ro, rw, local, landlock}]`：这一轮挂上的工作目录，`local` 表示在这个内核的机器上。没有工作目录的管理员会拿到一个 HOME 工作目录（`dirs` 为空、`ro` 为 `/`、`home` 为 true）：相对路径和 Shell 用 HOME，默认只能写临时目录；带 `elevated` 的调用批准后 `rw` 加 `/`。
- 内核 → 网关 `exec {sid, id, name, args, workspace}`：请网关执行一次工具（工作目录不在这台机器上，或者 `Skill`）；网关回 `exec_result {sid, id, ok, content}`。
- 网关 → 内核 `run {id, req}` / `skill_put {id, skill, files}`：请这台电脑的内核代为执行、放技能文件，回 `run_result`。
- 内核 → 网关 `exec_cancel {sid, id}`：工具超时或这一轮被停止时取消；网关停止执行器（SSH 关掉通道，服务器上的执行器收到 EOF 后退出）。
- 详见 [protocol.md](protocol.md)。

## 安装

- **网关那台机器**：日常使用 `make install`（程序、配置、数据都在 `~/.nano-agent`，注册后台服务）；开发时源码目录里 `make run`（编译，前台起网关；网关自己启动本机内核）。
- **别的电脑**：`make installer` 生成单文件安装包 `dist/nano-kernel-install.sh`（脚本 + 内核源码），拷过去 `sh nano-kernel-install.sh --gateway 地址`。脚本装编译工具、编译、装到 `~/.nano-agent/kernel/`、写 `kernel.conf`、注册 systemd 用户服务（没有 systemd 就用后台进程），然后等网页上核对确认码。再运行一次是升级，`--uninstall` 卸载。源码目录里也能直接 `scripts/install-kernel.sh`。
- **SSH 服务器**：什么都不用装，在网页拓扑图「＋ 接入机器」节点里添加。

## 在聊天里管理网关

管理员会话额外有 `Gateway`（查询）和 `GatewayAdmin`（修改，任何模式都审批）。工具定义由网关加，内核只把它们当管理工具（`NA_TOOL_ADMIN`），调用时用 `exec` 交给网关。查询返回模型/SSH/工作目录/配对状态，不含密钥；修改直接调用 `models.Store`、`host.Manager`、`AddWorkspace`、`UpdateSession` 和配对 API，实时生效。`ssh_setup` 会等连接结果（在线/认证失败/超时）。监听地址等要重启的配置不开放。详见 [DESIGN-agent-gateway-admin.md](DESIGN-agent-gateway-admin.md)。

## 活的 agent 和长期记忆（v0.6）

详细设计见 [DESIGN-v0.6-living-agent.md](DESIGN-v0.6-living-agent.md)。都在网关里（`gateway/internal/app` 的 `memory.go`、`dream.go`、`life.go`、`group.go`，`gateway/internal/knowledge`），内核只是把这几个网关工具（`Knowledge`、`Diary`、`FollowUp`、`Message`）转给网关执行：

```
 聊天（私聊 / 外部群 / 网关里的群）     内心活动（拟人型）          整理记忆（做梦）
 听 → 触发 → 不调模型的门槛 → 说/不说    @<id>/life，作息里自己醒     @<id>/dream，空闲/定点/睡着时
   读：消息前面放记忆说明、想起来的        冲浪、想事、找人（Message）   读日记（原始聊天记录）
   写：Knowledge                         最后一句是近况               写知识库、画像、自我认知
            └──────────── agents/<id>/knowledge（一条一个 .md）+ self.md ────────────┘
```

- 缓存优先：记忆说明、近况像环境说明一样放在用户消息前面，变了才放；系统提示只在类型改变时变（拟人守则）。
- 策略在技能里：怎么整理记忆是 `skills/dream/SKILL.md`，醒来干什么是 `skills/life/SKILL.md`，用户能改，agent 自己的 `agents/<id>/skills/` 优先。

## 聊天平台和放行模式（v0.7）

详细设计见 [DESIGN-v0.7-channels.md](DESIGN-v0.7-channels.md)。

- 渠道（`gateway/internal/channel`）都实现同一个 `Channel` 接口，能力按需实现：`Streamer`（流式卡片）、`Approver`（审批按钮）、`Typer`（正在输入，定时调）、`Busy`（处理时的状态，开始/结束各一次）、`Markdowner`（回复正文按 Markdown 发）。agent 的回复正文走 `deliverReply`，命令和系统说明走 `deliver`。
- QQ（`qq.go`）：官方机器人，WebSocket 网关收事件，HTTP 发消息；被动回复自动带最近一条消息的 `msg_id`。微信（`weixin.go`）：官方 ClawBot 的 iLink 接口，长轮询；回复带 `context_token`，游标和凭证存在 `data/bots/<id>.state.json`。两者都只能另外加（`bots.json`），扫码绑定（`register.go`、`qq_register.go`、`weixin_register.go`，网页接口在 `web/botreg.go`）。
- 放行模式（`full`）只在网关里：发给内核的是 `auto`，内核的沙箱和审批规则不变，`approve_req` 由网关当场批准（`approvals.go` 的 `autoApprove`）。拟人型没设置时默认放行。

## 安全

- 网页只听本机、密码登录。
- 内核口令：
  - 共用口令，给本机的内核用；
  - 配对得到的专用口令，绑定内核名字，网关只存 SHA-256。
- SSH 凭据只在网关（`data/connections.json`，0600，密码加密），密码经 `SSH_ASKPASS` 传递，不进命令行参数和日志。
- 模型 API key、SSH 密码、机器人 token、网页密码用 `~/.nano-agent/secret.key` 做 AES-256-GCM，存成 `enc:v1:...`；旧明文启动时自动加密重写。工具结果可以按 `[security] redact` 脱敏。
- 读：管理员会话能读当前用户能读的文件（访客仍然只读工作目录和系统目录）；写：默认只有工作目录、临时目录和缓存目录。写工作目录外要给 `Write` / `Edit` / `Shell` 加 `elevated: true`，任何模式都要审批（放行模式下由网关自动批准），批准后这一次调用 `rw` 放开到 `/`；访客和 readonly 模式不能提权。没有工作目录的管理员在 HOME 下工作。
- 工作目录不能包含网关的运行时、配置和数据目录（用 `make install` 后它们在用户目录，源码目录和项目目录不受影响），网关、内核和执行器各自把关。
- 内核连不上、被拒（名字冲突之类）时重连间隔逐渐拉长（最长 30 秒），网关接受之后才重置。
