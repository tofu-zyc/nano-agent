# v0.9.0 会话存储与恢复

逻辑会话 ID、平台绑定和用户身份保持原值。文件名使用 UTF-8 十六进制键，长 ID 使用哈希键及持久映射。新写入不再用平台 ID 直接创建文件或 NTFS 数据流。

- 历史、设置、分支：`data/v1/sessions/`。
- reset 归档：`data/v1/archive/`。列举、读取、计数、删除和清理使用同一个已发布视图。
- 人格和持久插话：各自目录的 `v1/<key>.md`、`v1/<key>.jsonl`；发布记录在 `data/v1/assets/`。
- 迁移来源身份：`data/v1/legacy-ownership/`。Windows 不把大小写不同的逻辑 ID 当作同一会话；既有平台绑定用于识别旧数据流的原始归属，歧义会报告错误。

启动先恢复重命名和提升，再盘点旧布局。Windows 使用系统数据流枚举接口，普通目录列举看不到的旧 ADS 也会被盘点。每份迁移来源先生成可见普通文件备份，保存长度、SHA-256 和来源记录，再按固定缓冲区复制并校验目标。原文件和原数据流保留。

`data/v1/legacy-backups/` 保存上述备份。发现的 `.tmp`、`.new`、`.bak` 候选也保留到 `candidates/` 并写入迁移报告，不自动选择它们作为正文。`data/v1/sessions/keys/migration.json` 是本次盘点报告；恢复依赖逐项操作记录，不依赖这份报告。

未提交副本不能仅凭文件存在获得发布权。操作绑定来源、目标、世代、上下文版本和内容版本；reset、删除和新一代会使旧发布授权失效。失效来源不会通过换操作 ID 再次导入。人格在普通 reset 后保留，尚未提交的人格导入和重命名则受 reset 撤销。删除并重建同 ID 不继承旧人格或旧插话。

人格和插话参与可恢复重命名。来源提交点之前，目标辅助文件处于 `rename_pending`，普通读写不会激活；提交之后才成为活动视图。重命名失败时保留双方和操作现场，不覆盖冲突文件。

网页概览会显示恢复错误；受影响会话不能悄悄回退到旧正文继续运行。修复来源权限、磁盘或冲突后重启会按原记录重试。不要删除发布记录、撤销标记或修改操作 ID 来强制恢复；这些文件用于防止旧内容复活。需要人工选择冲突正文时，先完整备份安装目录，在独立副本核对来源、目标和记录中的长度及校验和。

辅助目录的持久根引用相对于数据目录保存，整个安装目录搬迁后保持同一视图，避免重新导入已编辑前的旧副本。跨磁盘卷的独立目录保留绝对根绑定，改变配置后归属不匹配会明确失败。

已验证：Linux 全量 Go 测试及 vet、针对会话/插话/Fork 的 race、网页类型检查和构建；原生 Windows 上的 ADS 迁移、大小写归属、重启读取、可见备份、辅助文件重命名中断恢复与 reset 撤销、目录搬迁。测试不等同于对用户实际数据目录执行过迁移。
