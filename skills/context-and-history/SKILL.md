# 上下文和历史

## 看现在用了多少

`Gateway {"what":"session"}` 里的 `context`：`total`（现在的上下文 token 数，按接口返回的真实用量算）、`window`（模型窗口）、`auto_at`（到多少自动整理）、各部分（人格、工具定义、摘要、对话、工具结果）、`compacted`（已经整理掉的消息数）、`last`（上一次请求的输入、缓存命中、输出）。用户自己发 `/context` 也能看到同样的内容。

## 自动整理是怎么回事

上下文到窗口的 75%（`context.compact_at`）时自动整理到 40%（`context.compact_to`）：

1. 先把旧的、超过 2KB 的工具输出换成一行占位（“已省略：Read a.go 的输出，需要时重新读取”）；
2. 还不够，再把更早的对话分块合成一段摘要（目标、做过的决定、涉及的机器和文件、没做完的事、用户偏好、关键结论）；
3. 最近几轮（`context.keep_turns`，默认 4）一字不动，正在进行的这一轮绝不丢。

一轮结束后快到阈值、或者会话空闲 30 分钟（`context.idle_compact`），会在后台先整理好。看到旧工具输出变成了占位，需要时**重新读文件**，不要凭记忆编。

## 用户想手动处理时

这些命令只能用户自己发，你发不了；告诉用户发哪个：

- `/compact`：马上整理；`/compact 保留部署相关的细节` 把要特别保留的重点交给摘要。只压上下文，不丢原始记录。
- `/reset`：清空上下文，旧对话挪到归档（默认留 90 天）。
- `/reset 删除`：清空并直接删掉，不留归档。
- `/undo`（或者直接发「撤回」）：撤回最近一条消息，连同它的回复和工具调用。

## 删掉某几轮对话

用户说“把刚才那段删了”“删掉关于 X 的那几轮”：

1. `Gateway {"what":"turns"}` 列出最近的轮次：`turn` 是编号（从 0 起，整个历史文件里第几轮用户消息）、`text` 是用户说的话、`in_context` 为 false 表示已经整理进摘要、`running` 是正在执行的这一轮（不能删）。
2. 确定范围后：`GatewayAdmin {"action":"history_delete","from":5,"to":7}`（含 7）；全部历史连同归档：`{"action":"history_delete","all":true}`。删除是永久的，每次都要管理员审批；说清楚要删哪几轮再提交。
3. 删的是已经整理进摘要的部分时，摘要里可能还留着概要，告诉用户可以在网页会话里“清空摘要”。

## 调整自动整理

先 `Gateway {"what":"settings","group":"memory"}` 看当前值，再用 `GatewayAdmin {"action":"settings_set","key":"…","value":…}` 改：

| key | 意思 | 默认 |
|---|---|---|
| `context.compact_at` | 到窗口的这个比例自动整理 | 0.75 |
| `context.compact_to` | 整理到这个比例 | 0.4 |
| `context.keep_turns` | 最近几轮原样保留 | 4 |
| `context.idle_compact` | 空闲多久后台整理一次，`"0"` 关闭 | `"30m"` |
| `context.idle_compact_min` | 空闲整理只在超过这个比例时做 | 0.3 |
| `context.archive_days` | `/reset` 的归档留几天，0 永久 | 90 |

改完立即对所有会话生效。不要为了“省空间”主动去删用户的历史，删除只在用户明确要求时做。
