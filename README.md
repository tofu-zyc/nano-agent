# nano-agent

一个轻量的 bot 型 AI agent，拆成两个小程序：

- **内核**（C，除内嵌的 cJSON 外没有依赖）：只跑 agent 循环，负责预算、权限模式和审批。工具交给执行器 `nano-exec`，在沙箱里执行。
- **网关**（Go）：保存对话上下文，对接模型（任何 OpenAI 兼容接口）和聊天平台（Telegram、飞书、命令行、网页），自带一个网页管理界面。

两者通过一条一行一条 JSON 的连接通信（[协议说明](docs/protocol.md)），可以跑在同一台机器上，也可以分开：比如网关在 VPS 上，内核在家里的机器上执行工具。网关可以同时连着好几个内核（节点）：内核没有状态，上下文都在网关，一台机器关机了，别的内核能顶上（见[多个内核](#多个内核节点)）。

```
聊天平台（Telegram / 飞书 / 命令行）
   |
网关 Go     平台适配 · 会话上下文 · 人格 · 模型接入 · 工作目录设置
   |        NDJSON over Unix socket / TCP，由内核主动连网关
内核 C      循环状态机 · 步数和时间预算 · 权限模式与审批
   |        每次工具调用启动一次执行器：请求走 stdin，结果走 stdout
nano-exec   Read / Write / Edit / Grep / Shell，关在 Landlock + seccomp 沙箱里
```

## 快速开始（本机）

需要 gcc 或 clang、make、Go 1.22 以上。沙箱需要 Linux 5.13 以上（WSL2 也可以，支持 Windows 盘符下的工作目录）。

```sh
cp gateway.example.toml gateway.toml   # 填模型的 base_url / api_key / model，
cp kernel.example.conf kernel.conf     # 两边的 token 改成同一串随机字符
make run
```

`make run` 会编译三个程序，后台启动内核，前台启动网关，Ctrl-C 一起停掉。它会打印网页管理界面的登录链接；网关不占用这个终端的输入。网页、终端、Telegram 和飞书都支持边生成边显示回复，思考过程和工具调用也能看到。

在终端里聊天，另开一个终端：

```sh
make chat        # 也就是 ./gateway/nano-gateway chat -c gateway.toml
```

随时进出（Ctrl-D 或 Ctrl-C 退出），网关照常运行；连上时会先显示这个会话最近的几轮对话。同一时间只接一个终端，新开的会顶掉旧的。回复边生成边显示，思考过程和工具调用是灰色的，每轮结束后会显示用量和前缀缓存的命中率：

```
写个脚本打印 1 到 5 的平方并运行
思考> 用户要……
  ⚙ Write  squares.py（38 字节）
    ✓ 已创建 /home/me/foo/squares.py（2 行，38 字节）
  ⚙ Shell  python3 squares.py
    ✓ 1（共 5 行）
bot> 结果是 1、4、9、16、25。
  3 次模型调用 · 输入 9120 tokens（缓存命中 96%） · 输出 210（思考 120） · 用时 4.2s
```

日志在 `data/kernel.log` 和 `data/gateway.log`，另开一个终端 `tail -f data/*.log` 能看到每次模型调用和工具执行。

想让它读写文件、执行命令，先给它一个工作目录：

```
/dir add ~/projects/foo
/mode auto
```

`make run` 会打印一行 `网页管理界面：http://127.0.0.1:7788/#k=…`，用浏览器打开就自动登录了（见下面的[网页管理界面](#网页管理界面)）。

也可以分开启动：

```sh
make
./gateway/nano-gateway -c gateway.toml
./kernel/nano-kernel -c kernel.conf      # 另一个终端；-t 只检查配置和执行器，-v 打印协议消息
```

## 网页管理界面

网关自带一个网页界面，默认在 `http://127.0.0.1:7788`。密码在 `gateway.toml` 的 `[web] password` 里，没设置就自动生成一个，存在 `data/web.secret`；启动时打印的链接里带着密码，点开就登录了。

- **拓扑**（首页）：一张实时的关系图，从左到右依次是渠道（终端、网页、Telegram、飞书，以及它们的在线状态和机器人名字）、会话、网关、模型和内核、工作目录。消息进出、模型生成、工具执行时，连线上有光点沿着数据流动的方向跑；正在处理的会话外面有一圈光环，颜色表示它在思考、回复还是执行工具，有待审批时会出现黄色的提醒。
- **点哪儿改哪儿**：点图上的任何一个节点，右边展开它自己的状态和设置——点模型就是接口、思考强度、上下文长度，还能“测试连接”；点 Telegram 就是 token、代理、接入步骤；点飞书可以扫码创建机器人；点会话就是它的权限模式、工作目录、思考强度、人格。改完立即生效，不用点保存。节点可以拖动，摆好的位置会记住。
- **选目录不用记路径**：填工作目录时输入框会自动列出内核那台机器上的子目录（Tab 补全），也可以点“浏览…”一层层选；包含 nano-agent 自己的目录会标出来，不能选。
- **⌘K / Ctrl+K**：搜索所有配置项、会话和操作，比如输入“代理”“token”“思考”，回车直接跳到那一项。
- **会话**：所有会话的对话，带思考过程（可折叠）、工具调用卡片（参数和结果）、每次调用的用量和缓存命中率；正在处理的会话实时显示；待审批的工具调用可以直接点“批准 / 拒绝”。网页能往任何一个会话里发消息，网页用户都是管理员。会话的设置面板里能改名字、删除会话，还能把别的聊天窗口改接到这个会话上。
- **人格**：编辑默认人格和各个会话的专属人格，保存后下一条消息生效。
- **设置**：按对象分组的全部配置项，可以搜索、只看改过的。

网页里改的配置存在 `data/config.json`，叠加在 `gateway.toml` 上（优先级：配置文件 < 环境变量 < 网页）。每一项旁边的小圆点表示当前值来自哪里，改过的可以一键恢复成配置文件里的值。大部分修改立即生效（换模型、开关 Telegram / 飞书都不用重启）；少数几项（内核监听地址、网页地址等）会标着“重启生效”。

界面默认只监听本机。要从别的机器访问，建议用 SSH 隧道（`ssh -L 7788:127.0.0.1:7788 机器`）或者 Tailscale，而不是直接监听公网地址。

## 改人格（系统提示词）

人格文件在 `personas/` 目录下：

- `personas/default.md`：默认人格，所有会话都用它。
- `personas/<会话ID>.md`：给某个会话单独设定，比如 `personas/main.md`（主会话）、`personas/tg:123456789.md`（某个人私聊机器人的会话）。会话 ID 在聊天里发 `/whoami` 查，网页的会话设置里也可以直接点“给这个会话单独设定人格”。

**改完保存，下一条消息就生效，不用重启。** 历史里还留着旧人格说过的话，人格改动大的话可以发一次 `/reset` 清空上下文。

目前只支持私聊；机器人被拉进群、在群里被 @ 时会回一句“暂时只支持私聊”，其余群消息忽略。

## 工具

基础工具是固定的五个，内置在执行器里；安装技能后还会提供 `Skill`：

| 工具 | 作用 | 类别 |
|---|---|---|
| `Read` | 读文件（带行号，可分段），读目录时列出内容 | 只读 |
| `Grep` | 搜索文件内容，或按文件名列文件（有 ripgrep 就用它，没有退回 grep） | 只读 |
| `Write` | 新建或覆盖文件 | 写 |
| `Edit` | 把文件里的一段原文精确替换成新文本 | 写 |
| `Shell` | 用 `/bin/sh` 执行命令，默认超时 120 秒，最长 600 秒 | 命令 |
| `Skill` | 按需加载一个技能的说明，提供附带脚本和资料的位置 | 只读 |

基础工具定义固定不变，技能的名称和简介也只有在安装、删除、修改简介时才变化，方便模型的前缀缓存命中。

## 技能（Skill）

技能采用 Agent Skills 的目录格式，放在**内核所在机器**上，默认是 `kernel.conf` 旁边的 `skills/`，也可以用 `skills = /路径` 指定：

```text
skills/
  demo/
    SKILL.md
    scripts/run.sh
    references/notes.md
```

`SKILL.md` 示例：

```markdown
---
name: demo
description: 处理某类任务时使用的操作步骤
---
先用 Read 阅读 references/notes.md，再按需要用 Shell 运行 scripts/run.sh。
相对路径都以 Skill 返回的技能目录为基准。
```

模型平时只看到技能的名称和简介，需要时调用 `Skill` 才读取正文。技能目录在工具沙箱里只读可见，脚本仍按会话的权限模式执行。没有工作目录时依然只聊天，不提供工具。

新增、删除或修改技能后不用重启：下一轮请求会重新扫描，空闲时每 30 秒刷新一次；网页里点内核节点能看到已安装的技能。只修改正文和附带文件不会改变工具定义，正文在调用时重新读取。

会话通过 SSH 在服务器上工作时，使用的是负责连接它的内核上的技能；调用 `Skill` 时会将该技能目录上传到服务器的 `~/.cache/nano-agent/skills/`，返回服务器上的目录，后续 `Read`、`Shell` 可以直接使用其中的文件。本机和服务器都需要 `tar`。技能目录应由管理员安装和维护。

## 工作目录和权限

**工作目录**是工具能碰到的范围。所有工具都在沙箱里执行：

- 工作目录：可读写（只读模式下只读）；
- 系统目录（`/usr`、`/etc` 等）、`PATH` 里的命令：只读；
- 每个会话自己的临时目录（`$TMPDIR`）和共用的缓存目录：可读写；
- 其他地方，包括 HOME 里的其他东西、`/tmp`：一律访问不了；
- 不能连 unix socket（防止借 D-Bus、systemd、docker 在沙箱外执行命令），不能给沙箱外的进程发信号；
- 环境变量只保留 `PATH`、`HOME`、`LANG` 等少数几个，shell 配置里 export 的密钥带不进去。

沙箱用的是 Linux 自带的 Landlock 和 seccomp，普通用户就能用，不需要 root 和容器。机器不支持 Landlock 时（比如很老的内核），文件工具仍然只能访问工作目录，但 Shell 没有沙箱，自动模式下也会改为每次审批。

**权限模式**决定工作目录内的操作要不要先问：

| 模式 | 读文件、搜索 | 写文件 | 执行命令 |
|---|---|---|---|
| `auto` 自动 | 直接执行 | 直接执行 | 直接执行 |
| `ask` 审批 | 直接执行 | 管理员批准后执行 | 管理员批准后执行 |
| `readonly` 只读 | 直接执行 | 不允许 | 不允许 |

工作目录之外的操作在任何模式下都不允许，需要的话把目录加进来。**没有工作目录的会话只能聊天**：不给模型提供任何工具，并告诉它这一点。

**设置方法**：`gateway.toml` 的 `[workspace]` 是默认值；每个会话可以用 `/dir`、`/mode` 单独改，改动保存在 `data/sessions/` 下，下一条消息开始生效。工作目录或模式变化时，网关会在下一条用户消息前加一句 `[系统] 工作目录：…` 告诉模型，而不是去改系统提示词，这样前缀缓存不会失效。

几条限制：

- 工作目录不能包含 nano-agent 自己：配置文件里有密钥，执行器要是能被改写，沙箱就形同虚设。内核和网关都会拒绝这样的目录，所以别把 nano-agent 装在要让 bot 工作的目录里。
- 严格限制之后，有些工具需要额外放行。默认已经只读放行了 `~/.gitconfig`（git 提交需要用户名和邮箱）；npm、cargo 之类写缓存的，在 `[workspace]` 的 `extra_rw` 里加对应目录。
- 命令结束时，它启动的后台进程会被清理。

## 管理员

- **把自己设为管理员**：先私聊机器人说一句话，然后在网页里点拓扑图上的「飞书」或「Telegram」，“聊过天的人”里找到自己，点「设为管理员并接到主会话」。也可以手动写进 `gateway.toml` 的 `[access] admins`（比如 `"tg:123456789"`、`"feishu:ou_xxx"`），自己的身份在聊天里发 `/whoami` 查看。命令行和网页用户始终是管理员。
- 不是管理员时，`/session` 只显示自己的会话，并提示怎么成为管理员。
- 只有管理员能用写文件、执行命令这类工具，能改工作目录和模式，能审批。
- 其他人默认只能聊天（`guest = "none"`）；设成 `readonly` 的话可以读工作目录里的文件和搜索。
- 需要审批时，bot 会在聊天里发 `⚠️ 需要审批 #3`，写清楚要执行的命令或要改的文件，管理员回复 `/approve 3` 或 `/deny 3`。超时（默认 300 秒）按拒绝处理。

## 会话和聊天窗口

**会话**是一段对话：上下文、工作目录、权限模式、思考强度、人格。**聊天窗口**是终端、你和 Telegram 机器人的私聊、你和飞书机器人的私聊。每个窗口接在一个会话上，一个会话可以同时接好几个窗口：

- 管理员的窗口默认都接在**主会话**上：在终端、网页、Telegram、飞书说的话是同一段上下文，回复发回说话的那个窗口。
- 终端如果也接着这个会话，别的窗口说的话和回复会同步显示出来，前面标着 `[Telegram · 名字]`、`[网页]`。
- 其他人私聊机器人，各自一个会话，互相看不到，也看不到主会话。
- 每条用户消息前的时间戳里写着来源（`[2026-10-21 周三 15:08 · Telegram]`），模型知道你是从哪儿说的。
- 想开一段新的对话：`/session new 名字`，这个窗口就接到新会话上了；`/session` 列出所有会话，`/session 1` 切回主会话。网页里点“新建会话”，或者在会话设置里把某个窗口改接过来。
- **跨端自动同步**：接在同一会话的终端、Telegram、飞书会自动显示其他端的用户消息和回复，不用先在那个窗口发言。`/history` 或 `/sync` 随时补看最近的对话（`/history 10` 看 10 轮）；即使模型上下文已经压缩，仍能查看原始聊天记录。切换会话、设为管理员和重新接入时也会补上最近的对话，已看位置保存在 `data/endpoints.json`。Telegram 的命令菜单里也能直接找到历史、同步和会话。
- 网页能看到所有会话，也能往任何一个会话里发消息。主会话一直接着网页；在网页里新建或者说过话的会话，也算网页接着（拓扑图里会连上线）。

接线存在 `data/endpoints.json`。从旧版本升级时，原来终端的会话 `cli:local` 会自动并入主会话。

## 聊天命令

| 命令 | 作用 |
|---|---|
| `/help` | 列出命令 |
| `/whoami` | 显示你的身份、这个窗口和它接着的会话（配置管理员、单独人格时要用） |
| `/session` | 列出所有会话；`/session <编号或名字>` 把这个窗口切到那个会话，`/session new [名字]` 新建一个会话并切过去（切换需管理员） |
| `/history`、`/sync` | 查看当前会话最近 5 轮原始对话；加轮数看更多（最多 30 轮）；同一会话内也会自动同步 |
| `/node` | 查看这个会话在哪台机器上工作、哪些机器在线；`/node <名字>` 切换，`/node default` 用默认的机器（切换需管理员） |
| `/dir` | 查看工作目录；`/dir add <路径> [ro]` 添加（`ro` 表示只读），`/dir rm <路径>` 移除，`/dir default <路径>` 设为默认 |
| `/mode` | 查看权限模式；`/mode auto\|ask\|readonly` 切换 |
| `/think` | 查看思考强度；`/think none\|low\|high…` 切换（`none` 是关闭，可选值见 `llm.thinking_levels`），`/think default` 恢复默认 |
| `/stop` | 停止当前任务（正在执行的命令会被杀掉） |
| `/reset` | 清空本会话的上下文（工作目录和模式保留） |
| `/approve <编号>` / `/deny <编号>` | 批准或拒绝一次工具执行 |

目前只支持私聊，群聊以后再做。

## 接入 Telegram

1. 找 [@BotFather](https://t.me/BotFather) 发 `/newbot`，拿到 token，填进 `gateway.toml` 的 `[telegram]`，并设置 `enabled = true`。
2. 国内访问 Telegram 需要代理：`proxy = ""` 表示用网关的默认代理（`[network] proxy`，它留空就跟随环境变量 `HTTPS_PROXY`），也可以直接写 `proxy = "http://127.0.0.1:7890"`。
3. 用的是长轮询，不需要公网地址。私聊机器人就能用（目前只支持私聊）。

回复正文单独发送并持续编辑，默认每秒合并更新一次；长回复按 UTF-16 长度分段，兼容 emoji。思考、工具记录和统计放在独立的过程消息里，思考和工具使用 Telegram 原生可展开引用，默认收起。大量调用仅保留有限长度的过程预览，完整记录在网页中查看；更新失败时补发正文，不把原始过程重新灌进回复。

## 接入飞书

用的是飞书开放平台的长连接模式，不需要公网地址，也不用配置加密。

**最简单的办法是扫码创建**：在网页管理界面点拓扑图上的“飞书”节点 → “生成二维码”，用飞书扫一扫、在手机上确认，网关会自动拿到 App ID 和 App Secret、写进配置并启动飞书渠道（走的是飞书开放平台官方的应用注册接口）。创建好之后私聊机器人试试；如果没反应，到开放平台看一下这个应用：事件订阅方式要是“长连接”，并且已经发布了版本。

也可以手动创建：

1. 在[飞书开放平台](https://open.feishu.cn/app)创建企业自建应用，在"添加应用能力"里加上**机器人**。
2. 在"凭证与基础信息"里拿到 App ID 和 App Secret，填进 `gateway.toml` 的 `[feishu]`，并设置 `enabled = true`，然后启动网关。
3. 在"事件与回调"里把订阅方式设为**使用长连接接收事件**。如果保存时提示检测不到连接，确认网关已经在运行，再保存一次。
4. 添加事件 **接收消息 v2.0**（`im.message.receive_v1`），按提示开通配套权限。还需要的权限：
   - `im:message`、`im:message:send_as_bot`：收发消息；
   - `cardkit:card:write`（创建与更新卡片）：流式回复需要；以前创建的应用要补开这个权限并发布新版本；
   - 读取用户发给机器人的单聊消息：添加事件时会提示；
   - 可选 `contact:user.base:readonly`：读取用户姓名（没有的话用"用户xxxx"代替）。
5. 创建版本并发布（企业里一般要管理员审核），然后私聊机器人。

具体按钮名称以飞书后台为准，后台改版后可能会变。

飞书使用 [CardKit 流式卡片](https://open.feishu.cn/document/cardkit-v1/card-element/content)，默认每半秒合并更新一次。处理过程和回复分成独立卡片，过程卡里的思考和工具记录默认折叠，统计单独显示；正文支持 Markdown，长回复拆分为多张回复卡，不重复堆放工具记录。过程预览限制长度，完整记录可在网页查看。扫码创建的新应用会申请卡片权限；未开通权限或更新失败时补发正文。审批继续使用 `/approve`、`/deny`，也可以在网页操作。

## 多个内核（节点）

网关是唯一有状态的中心：上下文、会话、聊天窗口、审批都在网关。内核是无状态的工人，每个内核是一个节点（一台能干活的机器：家里的电脑、手机、服务器……），可以同时连好几个，按 `kernel.conf` 里的 `node` 区分（默认是主机名，名字不能重复）。

- **每个会话在一台机器上工作**：工作目录是那台机器上的路径。会话设置里选机器（或者在聊天里 `/node <名字>`），没选就用默认机器：配置里的 `workspace.node`，没配就是和网关在同一台机器上的内核。换机器时，原来那台机器上的工作目录会清掉。
- **替补**：会话的机器不在线时（比如电脑关机了），网关找一个在线的内核顶上（和网关同一台机器的优先，其次是最近连上来的）。这一轮照常回复，但碰不到那台机器上的文件，所以只聊天、不给工具，并告诉模型原因；那台机器连回来后自动恢复。没有工作目录的会话，哪个内核在线都一样。
- **掉线**：内核断线后会自动重连。断线时它正在跑的那一轮作废（正在执行的命令会被杀掉），聊天里会收到提示，排队的消息交给别的内核。
- 拓扑图右边列出所有机器，在线的实线、离线的虚线，工作目录挂在它所在的机器下面；点开能看到每台机器的沙箱和在上面工作的会话。

**服务器（SSH 远程执行）**：服务器上不用跑内核。在某个内核的 `kernel.conf` 里加一行 `remote = prod deploy@prod.example.com`（这台机器要能免密 ssh 过去），这台服务器就成了一个节点：

- 内核启动后在后台准备执行器：服务器上没有这个版本的 `nano-exec` 就传一份到 `~/.cache/nano-agent/`；传上去跑不起来（架构不同、glibc 太老）而服务器有 `cc`，就把源码传过去现编。也可以自己在服务器上装好，在那一行后面写上路径。本机能静态链接时（装了 glibc-static 或 musl），`make` 会顺带编一个 `nano-exec-static`，优先传它。
- 会话选它之后，循环还在那个内核上跑，每次调用工具时通过复用的 SSH 连接（ControlMaster）在服务器上临时运行一次执行器，同样关在服务器的 Landlock 沙箱里（服务器不支持的话，自动模式下的 Shell 每次要审批）。工作目录是服务器上的路径，网页里也能直接浏览服务器上的目录。
- 服务器连不上时和机器离线一样：这一轮由替补只聊天，并说明原因；内核每分钟重试一次。好几个内核都能连到同一台服务器时，任何一个在线都行。
- 服务器上的执行器会检查：可写的工作目录不能包含它自己（比如工作目录设成 `~`），否则拒绝执行。

在另一台机器上加一个内核：

- 网关：`[kernel] listen = "tcp:0.0.0.0:7700"`（让那台机器连得到）。
- 内核：`gateway = tcp:网关地址:7700`，`token` 和网关一致，`node = 起个名字`。
- 协议本身不加密，跨公网时请走 WireGuard、Tailscale 或 SSH 隧道（比如 `ssh -L 7700:127.0.0.1:7700 vps`，内核连 `tcp:127.0.0.1:7700`）。

## 模型接入

任何 OpenAI 兼容的 `/chat/completions` 接口都能接，比如 vLLM、DeepSeek、通义、Kimi。请求走流式接口。几个注意点：

- **代理**：模型、Telegram、飞书各自的 `proxy` 留空时用网关的默认代理 `[network] proxy`；它也留空就跟随环境变量。Go 不认 `NO_PROXY` 里 `10.*` 这种通配写法，**内网的模型地址要显式写 `proxy = "none"`**（直连），否则请求会被发到代理上。
- `[llm.extra]` 里的参数会原样合并进请求体。
- **思考强度**：作为顶层的 `reasoning_effort` 原样传给模型（vLLM 等兼容接口也认），`none` 表示关闭。默认值是 `thinking`（空表示不传），每个会话可以用 `/think` 单独改；可选的值在 `thinking_levels` 里，不同模型支持的不一样（比如有的不支持 `medium`）。

## 上下文和前缀缓存

模型服务一般都有前缀缓存：这次请求的开头和上次一样，那部分就不用重新计算，又快又便宜。网关的上下文管理围绕这一点设计——**每次请求都是上一次请求原样加上新消息**：

- 系统提示词（人格）和工具定义固定不变，里面不放时间、目录这类会变的东西。
- 时间和来源写在每条用户消息前面（`[2026-10-21 周三 15:08 · 命令行]`）；工作目录、权限模式变了，就在下一条用户消息前加一句 `[系统] …`。都是追加，不改前面的内容。
- 工具输出在写进历史时就截断定型，思考内容不回传，历史只追加。
- 历史超过 `max_history_tokens`（按字节数粗估）时，**一次**整理最早的一大段，保留 `trim_to` 的比例（默认一半），之后又只追加，直到下次超出；不会每次都裁一点（那样每次请求的开头都不一样，缓存永远不命中）。只在用户消息处切，工具调用和结果不会被拆开，当前这一轮始终完整保留。
- 整理时额外请求一次当前配置的模型，将旧对话与上次摘要合并，保存目标、决定、关键路径、结果和待办；不传工具和推理记录，输出上限 2048 token，可用时关闭思考，最多等 60 秒。摘要和工作目录信息放在剩余历史前面，后续请求保持这个前缀不变，用量计入本轮统计。生成失败时保留已有摘要并注明省略，不阻断正常回复；停止、清空会话也会取消摘要请求。
- 每次模型调用的缓存命中数记在日志里（`cached_tokens`），命令行每轮结束显示命中率。

对话历史存在 `data/sessions/<会话ID>.jsonl`，一行一条消息，只追加，压缩也不改写原始记录；重启后会恢复摘要和保留的上下文。会话设置（名字、工作目录、模式、思考强度、裁剪位置、摘要）在同目录的 `.settings.json` 里，聊天窗口接在哪个会话上记在 `data/endpoints.json`。

## 测试

```sh
make test
```

- `kernel/tests/test_core.c`：状态机单元测试（ASan + UBSan）。
- `kernel/tests/test_exec.py`：直接驱动执行器，测五个工具，以及各种绕过沙箱的尝试（`..`、符号链接、`~`、unix socket、发信号、环境变量里的密钥）。
- `kernel/tests/test_host.py`：用假网关驱动真实的内核和执行器，测权限模式、审批、超时、取消、断线重连、进程清理（ASan 版本）。
- `gateway/...`：Go 单元测试，`internal/app` 里用假内核走真实 socket 测调度逻辑（`-race`）。
- `gateway/internal/web`：网页接口的测试（登录、防跨站请求、Host 检查、改配置、事件流）。
- `scripts/e2e.sh`：真实的内核、执行器和网关一起跑，模型用 mock，不花钱。

前端代码在 `gateway/web/`（Svelte + Vite），构建结果放在 `gateway/internal/web/dist/` 并提交在仓库里，编译网关只需要 Go。改了前端之后运行 `make web` 重新构建（需要 Node 20 以上）。

把 `llm.provider` 设成 `mock` 就能不接模型调试整条链路：消息里写 `!call 工具名 {参数}` 会让假模型去调这个工具，比如 `!call Shell {"command":"ls"}`。
