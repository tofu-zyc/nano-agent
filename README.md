# nano-agent

一个轻量的 bot 型 AI agent，拆成两个小程序：

- **内核**（C，除内嵌的 cJSON 外没有依赖）：只跑 agent 循环，负责预算、权限模式和审批。工具交给执行器 `nano-exec`，在沙箱里执行。
- **网关**（Go）：保存对话上下文，对接模型（任何 OpenAI 兼容接口）和聊天平台（Telegram、飞书、命令行、网页），自带一个网页管理界面。

两者通过一条一行一条 JSON 的连接通信（[协议说明](docs/protocol.md)）。网关是唯一有状态的中心，可以同时连着好几个内核；内核没有状态，一台机器关机了，别的内核能顶上。工作目录可以在网关所在的本机、装了内核的电脑，或者网关通过 SSH 连的服务器上（服务器上只放执行器，不跑内核）。不管内核跑在哪里，都能在任何挂在网关上的工作目录里干活（见[机器和工作目录](#机器和工作目录)，设计说明在 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)）。

```
聊天平台（Telegram / 飞书 / 命令行 / 网页）
   |
网关 Go     平台适配 · 会话上下文 · 人格 · 模型接入 · 工作目录 · SSH 连接
   |        NDJSON over Unix socket / TCP              \ SSH（网关自己连）
内核 C      循环状态机 · 步数和时间预算 · 权限模式与审批      nano-exec（服务器上只有执行器）
   |        每次工具调用启动一次执行器：请求走 stdin，结果走 stdout
nano-exec   Read / Write / Edit / Grep / Shell，关在 Landlock + seccomp 沙箱里
```

## 安装

网关装在一台常开的 Linux 机器上（x86_64 / arm64），一行命令：

```sh
curl -fsSL https://github.com/tofu-zyc/nano-agent/releases/latest/download/install.sh | sh
```

装到 `~/.nano-agent`，注册成后台服务（有 systemd 用用户服务，没有就用后台进程 + 看护），打印网页地址；带密码的登录链接用 `nano-gateway url` 查看。再运行一次就是升级，配置和数据保留。

别的电脑上装内核，接到这个网关（网关的 `[kernel] listen` 要改成 `tcp:0.0.0.0:7700`）：

```sh
# Linux / macOS
curl -fsSL https://github.com/tofu-zyc/nano-agent/releases/latest/download/install.sh | sh -s -- --kernel --gateway tcp:网关地址:7700
```

```powershell
# Windows（PowerShell）
& ([scriptblock]::Create((irm https://github.com/tofu-zyc/nano-agent/releases/latest/download/install.ps1))) -Gateway tcp:网关地址:7700
```

装好后在网关网页的「设备」里核对确认码、点「允许」。下载慢时可以设 `NANO_DOWNLOAD_URL` 换成镜像地址。

把网关搬到另一台机器：

```sh
nano-gateway export                 # 旧机器上：配置、数据、密钥文件打成一个包（当密码一样保管）
curl -fsSL https://github.com/tofu-zyc/nano-agent/releases/latest/download/install.sh | sh -s -- --import nano-agent-export-xxx.tar.gz --old-local-as 旧机器名
```

### 更新和卸载

```sh
nano-gateway update --check       # 有没有新版本（网关每天也会查一次，只提示）
nano-gateway update               # 下载、校验、备份，用新程序检查配置后重启；新版本起不来自动退回
nano-gateway update --version 0.1.1   # 换成指定版本（也能退回旧版本）
nano-gateway uninstall            # 停服务，删程序、服务文件、PATH 行；同一个目录里装着内核时只卸网关
nano-gateway uninstall --keep-data    # 只删程序，配置和数据留着，以后重装接着用
```

聊天里管理员发 `/update`、网页设置页点「更新」、跟 AI 说“更新网关”（要批准）都行。自带的人格和技能：没改过的直接更新，改过的保留，新版本放成 `.new`。

接入的电脑上的内核**自动跟网关保持同一个版本**：内核连上来时版本不一样，网关就把同版本的内核推过去，内核换掉自己后重启，起不来自动退回（`[update] kernels = false` 关掉）。

### 管理内核（在装了内核的电脑上，Linux / macOS / Windows 一样）

```sh
nano-kernel status                    # 运行状态、和网关的连接（已连接多久 / 正在连接的报错 / 等确认的确认码）、版本
nano-kernel start | stop | restart    # 自动认出 systemd / launchd / Windows 任务计划或启动文件夹 / 后台进程
nano-kernel connect 192.168.1.2:7700 [--name 名字]   # 改连别的网关并重启；换了网关会自动重新申请接入
nano-kernel logs -f
nano-kernel update | uninstall
```

`nano-kernel help` 看全部命令，`nano-kernel 命令 --help` 看单个命令的用法。安装时会把 `nano-kernel` 加进 PATH（Windows 加进当前用户的 PATH，要新开一个终端）；以前的 `nano-kernel-ctl` 已经去掉，重新运行安装命令时会删掉。

Windows 上开机自启用任务计划程序（只对当前用户，不需要管理员）；建不了任务时（比如公司电脑的策略）自动改用「启动」文件夹里的快捷方式，`-NoTask` 也可以直接用这种方式。

`--old-local-as` 把旧网关“本机”上的工作目录改记到这个机器名下：之后在旧机器上装内核、用这个名字连过来，工作目录和会话都能接着用。配对过的电脑要改连新地址（在那台电脑上重新运行安装命令，配对口令保留）。

## 快速开始（从源码）

需要 gcc 或 clang、make、Go 1.22 以上。沙箱需要 Linux 5.13 以上（WSL2 也可以，支持 Windows 盘符下的工作目录）。

```sh
cp gateway.example.toml gateway.toml   # 把 token 改成一串随机字符；模型启动后在网页里添加
make run
```

`make run` 会编译三个程序，前台启动网关，Ctrl-C 停掉。网关自己会在本机启动一个内核（叫 `gateway`，退出了自动重启，日志在 `data/kernel.log`），不用另外写 `kernel.conf`。它会打印网页管理界面的地址（带密码的登录链接只写在 `data/web.url`，权限 0600）；网关不占用这个终端的输入。网页、终端、Telegram 和飞书都支持边生成边显示回复，思考过程和工具调用也能看到。

在终端里聊天，另开一个终端：

```sh
make chat        # 也就是 ./gateway/nano-gateway chat -c gateway.toml
```

随时进出（Ctrl-D 或 Ctrl-C 退出），网关照常运行；连上时会先显示这个会话最近的几轮对话。同一时间只接一个终端，新开的会顶掉旧的。回复边生成边显示，思考过程和工具调用是灰色的，每轮结束后会显示用量和前缀缓存的命中率：

```
写个脚本打印 1 到 5 的平方并运行
思考> 用户要……
  ⚙ Write  squares.py（38 字节）
    ✓ 已创建 /home/me/foo/squares.py（2 行，38 字节）
  ⚙ Shell  python3 squares.py
    ✓ 1（共 5 行）
bot> 结果是 1、4、9、16、25。
  3 次模型调用 · 输入 9120 tokens（缓存命中 96%） · 输出 210（思考 120） · 用时 4.2s
```

日志在 `data/kernel.log` 和 `data/gateway.log`（权限 0600），另开一个终端 `tail -f data/*.log` 能看到每次模型调用和工具执行。

### 查看和控制网关

`nano-gateway` 自己带一套管理命令，终端、网页和聊天里都能用：

```sh
nano-gateway status              # 版本、运行时长、内核、渠道、待重启设置和最近错误
nano-gateway start               # 启动（有 systemd 用服务，没有用后台进程并看护）
nano-gateway stop                # 停止
nano-gateway restart             # 先检查配置，再停止/启动；配置坏了会拒绝，网关保持运行
nano-gateway logs -f -n 100      # 看日志，-f 跟着滚
nano-gateway url                 # 打印带密码的网页登录链接
nano-gateway doctor              # 检查配置、密钥和目录权限、端口、执行器/内核、服务、WSL 保活
nano-gateway version             # 编译时写进去的版本号
nano-gateway help                # 全部命令；nano-gateway 命令 --help 看单个命令
```

聊天里管理员可以用 `/status` 和 `/restart`；网页设置顶部在改动了需要重启的配置时会出现“重启网关”按钮，重启期间页面显示“重启中”并自动重连；AI 可以在管理员会话里用 `Gateway {"what":"logs"}` 看脱敏日志，用 `GatewayAdmin {"action":"restart"}` 重启（要审批）。重启会先重新加载 `gateway.toml` 和 `data/config.json`，加载失败不会停掉正在运行的网关；成功后会给发起的会话回一句“网关已重启”。

后台进程模式有一个看护进程，网关异常退出（包括被 `kill -9`）后几秒会重新拉起；主动 `stop` 或自重启不会触发它。WSL 关掉所有终端后 Windows 可能停掉发行版，`nano-gateway doctor` 会提示用 Windows 启动文件夹里的隐藏 VBS 保活（安装脚本在 WSL 里会询问，`--wsl-keepalive` 可直接设置；不需要管理员权限，也不改 `.wslconfig`）。

想让它默认写文件、执行命令，先给它挂一个工作目录（网页里点对话顶部的“未挂目录”挂也行，可以同时挂好几个）：

```
/dir add ~/projects/foo
/mode auto
```

要在别的电脑或服务器上的目录里工作，见[机器和工作目录](#机器和工作目录)。

`make run` 会打印一行 `网页管理界面：http://127.0.0.1:7788/`；带密码的完整登录链接在 `data/web.url`（只有你能读），用浏览器打开就自动登录了（见下面的[网页管理界面](#网页管理界面)）。

### 装到用户目录（日常使用建议）

源码目录里的 `make run` 是开发方式，配置和数据会留在仓库里。日常使用装成后台服务，所有文件放在一个目录里：

```sh
make install
# 已有源码目录里的 gateway.toml 和 data/ 时，复制过去（源文件不动）：
# scripts/install-gateway.sh --migrate
# 卸载（会先问要不要删会话记录）：
# scripts/install-gateway.sh --uninstall
```

默认目录是 `~/.nano-agent`，可以用 `NANO_HOME` 改：

- `bin/nano-gateway`：网关程序（`nano-gateway chat` 也在这里）
- `lib/`：`nano-kernel`、`nano-exec` 和源码包
- `gateway.toml`：配置
- `personas/`、`skills/`：人格和技能
- `data/`：会话、模型、SSH 连接、图片、日志
- `secret.key`：第一次启动时生成的加密密钥（0600）
- `run/`：unix socket 和 SSH 控制 socket

安装脚本会问要不要把 `~/.nano-agent/bin` 加进 PATH；有 systemd 时注册用户服务（挂了自动重启），没有就用 `nano-gateway start|stop|status|logs` 在后台跑（旧的 `nano-gateway-ctl` 会被清理）。源码目录、项目目录和网关自己的文件是分开的，源码目录本身也可以设为工作目录；只有 `~/.nano-agent` 自己不能当工作目录。

想自己管本机的内核（比如调试内核）：在 `gateway.toml` 里设 `[kernel] local = false`，再照 `kernel.example.conf` 写一个 `kernel.conf` 手动启动：

```sh
./gateway/nano-gateway -c gateway.toml
./kernel/nano-kernel -c kernel.conf      # 另一个终端；-t 只检查配置和执行器，-v 打印协议消息
```

## 网页管理界面

网关自带一个网页界面，默认在 `http://127.0.0.1:7788`。密码在配置文件的 `[web] password` 里（安装版是 `~/.nano-agent/gateway.toml`），没设置就自动生成一个，加密存在数据目录的 `web.secret`；启动时打印的链接里带着密码，点开就登录了。

- **拓扑**（首页）：一张实时的关系图，从左到右依次是渠道（终端、网页、Telegram、飞书，以及它们的在线状态和机器人名字）、会话、网关、模型和内核、工作目录。消息进出、模型生成、工具执行时，连线上有光点沿着数据流动的方向跑；正在处理的会话外面有一圈光环，颜色表示它在思考、回复还是执行工具，有待审批时会出现黄色的提醒。
- **点哪儿改哪儿**：点图上的任何一个节点，右边展开它自己的状态和设置——点**模型**打开加宽的模型面板：左边接口/模型列表，右边详情，可以加接口、加模型、设默认、单独测试、删除，“测试”会真的发一个小请求；点 Telegram 就是 token、代理、接入步骤；点飞书可以扫码创建机器人；点会话就是它的模型、权限模式、工作目录、思考强度、人格。改完立即生效，不用点保存。节点可以拖动，摆好的位置会记住。
- **挂工作目录**：点对话顶部或会话设置里的工作目录，弹出的列表按机器分组，点一下挂上、再点一下取下，可以同时挂好几个、在不同的机器上；★ 标记新会话默认挂上的。列表里没有的，先选机器（本机、SSH 服务器、装了内核的电脑），再一层层浏览那台机器上的目录添加；网关自己的运行时、配置和数据目录会标出来，不能选。
- **右键菜单**：拓扑图上右键点节点有常用操作：模型节点可以直接添加模型/接口、测试默认模型；会话可以打开对话、挂载工作目录、停止、清空；机器可以浏览目录、断开 SSH；工作目录可以挂到主会话、设为默认。右键画布空白可以新增接口、工作目录，或去接入电脑。
- **命令提示**：对话输入框里打 `/` 会列出命令和用法，上下键选、Tab 补全、Enter 确定。
- **⌘K / Ctrl+K**：搜索所有配置项、会话和操作，比如输入“代理”“token”“思考”，回车直接跳到那一项。
- **会话**：所有会话的对话，带思考过程（可折叠）、工具调用卡片（参数和结果）、每次调用的用量和缓存命中率；正在处理的会话实时显示；待审批的工具调用可以直接点“批准 / 拒绝”。网页能往任何一个会话里发消息，网页用户都是管理员。会话的设置面板里能改名字、删除会话，还能把别的聊天窗口改接到这个会话上。
- **设备**：添加 SSH 服务器（主机、端口、用户、密码 / 密钥，或 SSH 配置里的别名），管理连接、断开和自动重连；别的电脑装内核的步骤、接入确认（配对）也在这里。
- **人格**：编辑默认人格和各个会话的专属人格，保存后下一条消息生效。
- **设置**：按对象分组的全部配置项，可以搜索、只看改过的。

网页里改的配置存在数据目录的 `config.json`，叠加在 `gateway.toml` 上（优先级：配置文件 < 环境变量 < 网页）。每一项旁边的小圆点表示当前值来自哪里，改过的可以一键恢复成配置文件里的值。大部分修改立即生效（换模型、开关 Telegram / 飞书都不用重启）；少数几项（内核监听地址、网页地址等）会标着“重启生效”。

界面默认只监听本机。要从别的机器访问，建议用 SSH 隧道（`ssh -L 7788:127.0.0.1:7788 机器`）或者 Tailscale，而不是直接监听公网地址。

## 改人格（系统提示词）

人格文件在 `personas/` 目录下：

- `personas/default.md`：默认人格，所有会话都用它。
- `personas/<会话ID>.md`：给某个会话单独设定，比如 `personas/main.md`（主会话）、`personas/tg:123456789.md`（某个人私聊机器人的会话）。会话 ID 在聊天里发 `/whoami` 查，网页的会话设置里也可以直接点“给这个会话单独设定人格”。

**改完保存，下一条消息就生效，不用重启。** 历史里还留着旧人格说过的话，人格改动大的话可以发一次 `/reset` 清空上下文。

目前只支持私聊；机器人被拉进群、在群里被 @ 时会回一句“暂时只支持私聊”，其余群消息忽略。

## 工具

基础工具是固定的五个，内置在执行器里；安装技能后还会提供 `Skill`：

| 工具 | 作用 | 类别 |
|---|---|---|
| `Read` | 读文件（带行号，可分段），读目录时列出内容 | 只读 |
| `Grep` | 搜索文件内容，或按文件名列文件（有 ripgrep 就用它，没有退回 grep） | 只读 |
| `Write` | 新建或覆盖文件 | 写 |
| `Edit` | 把文件里的一段原文精确替换成新文本 | 写 |
| `Shell` | 用 `/bin/sh` 执行命令，默认超时 120 秒，最长 600 秒 | 命令 |
| `Skill` | 按需加载一个技能的说明，提供附带脚本和资料的位置 | 只读 |

基础工具定义固定不变，技能的名称和简介也只有在安装、删除、修改简介时才变化，方便模型的前缀缓存命中。

## 技能（Skill）

技能采用 Agent Skills 的目录格式，放在**网关**上（所有内核共用），默认是 `gateway.toml` 旁边的 `skills/`，也可以用 `[skills] dir` 指定：

```text
skills/
  demo/
    SKILL.md
    scripts/run.sh
    references/notes.md
```

`SKILL.md` 示例：

```markdown
---
name: demo
description: 处理某类任务时使用的操作步骤
---
先用 Read 阅读 references/notes.md，再按需要用 Shell 运行 scripts/run.sh。
相对路径都以 Skill 返回的技能目录为基准。
```

模型平时只看到技能的名称和简介，需要时调用 `Skill` 才读取正文。调用时网关把技能的附带文件放到这个会话挂载的每台机器的 `~/.nano-agent/skills/<技能名>/` 下（每台机器上路径一样，只读可见），之后 `Read`、`Shell` 可以直接用；脚本仍按会话的权限模式执行。技能最多 4 MB、500 个文件，不跟随符号链接。没有工作目录时管理员在 HOME 下工作（读不限，写临时目录；写外面要提权），访客没有工具。

新增、删除或修改技能后不用重启：每一轮开始时重新扫描；网页里点顶栏的内核能看到技能列表。只修改正文和附带文件不会改变工具定义，正文在调用时重新读取。

仓库里自带 `device-connections` 和 `model-setup` 两个技能：前者讲机器、工作目录和接入，后者讲怎么在聊天里配置模型。

## 工作目录和权限

**工作目录**决定默认能写哪些文件。所有工具都在沙箱里执行：

- **读**：管理员会话能读当前用户能读的文件，包括系统目录、HOME、`~/.ssh` 和别的项目；访客仍然只能读工作目录和系统目录（`guest = "readonly"` 时）；
- **写**：挂载的工作目录、每个会话的临时目录（`$TMPDIR`）和缓存目录可写；
- **写工作目录外**：给 `Write` / `Edit` / `Shell` 加 `elevated: true`，每次都要管理员批准；批准后这一次调用的沙箱放开到整个文件系统（当前用户能写的地方），seccomp 和环境变量清理照旧；
- **没有工作目录**：在 HOME 下工作，`Read`、`Grep`、`Shell` 都能用，Shell 的当前目录是 HOME；默认只能写临时目录，要写 HOME 或其他地方同样用 `elevated: true`；访客没有工具；
- 访客不能提权；`readonly` 模式也不能提权；
- 不能连 unix socket（防止借 D-Bus、systemd、docker 在沙箱外执行命令），不能给沙箱外的进程发信号；
- 环境变量只保留 `PATH`、`HOME`、`LANG` 等少数几个，shell 配置里 export 的密钥带不进去。

沙箱用的是 Linux 自带的 Landlock 和 seccomp，普通用户就能用，不需要 root 和容器。机器不支持 Landlock 时（比如很老的内核），读的规则仍然由执行器限制，但 Shell 没有内核级沙箱，自动模式下也会改为每次审批。

**权限模式**决定工作目录内的操作要不要先问：

| 模式 | 读文件、搜索 | 写文件 | 执行命令 |
|---|---|---|---|
| `auto` 自动 | 直接执行 | 直接执行 | 直接执行 |
| `ask` 审批 | 直接执行 | 管理员批准后执行 | 管理员批准后执行 |
| `readonly` 只读 | 直接执行 | 不允许 | 不允许 |

带 `elevated: true` 的写文件 / 命令在任何模式（包括 `auto`）都要审批；`readonly` 和访客直接拒绝。

读取不受工作目录限制；**写工作目录外要 `elevated: true`，静默模式（auto）也要每次审批**。没有工作目录的会话在 HOME 下工作，不是只读模式；访客仍然没有工具。

**设置方法**：工作目录是一个列表（存在 `data/workspaces.json`），每一项是“机器 + 目录”，标 ★ 的新会话默认挂上。每个会话从列表里挂任意几个（可以在不同的机器上），一个都不挂就在 HOME 下工作：网页里点对话顶部或会话设置的工作目录，聊天里用 `/dir`。挂了好几个时，模型调用工具要用 `workspace` 参数写明在哪个上执行（写系统说明里列出的名字，比如 `gpu:~/train`）；同一台机器上挂的几个目录互相都能读写，方便在它们之间拷文件。权限模式默认是 `gateway.toml` 的 `[workspace] mode`，每个会话可以用 `/mode` 单独改。会话的设置保存在 `data/sessions/` 下，下一条消息开始生效。挂载或模式变化时，网关会在下一条用户消息前加一段 `[系统] …` 列出挂载的工作目录告诉模型，而不是去改系统提示词，这样前缀缓存不会失效。

几条限制：

- 网关自己的运行时、配置和数据目录不能当工作目录：配置里有密钥，执行器要是能被改写，沙箱就形同虚设。用 `make install` 安装后它们都在 `~/.nano-agent`，源码目录和项目目录不受影响。直接在源码目录里运行（`make run`）时，它们会留在仓库里，仓库及上级目录仍然不能当工作目录——这是开发方式，不是日常使用方式。
- 管理员会话可以读 `~/.ssh`、系统目录、其他项目；写默认只限工作目录、临时目录和缓存，写外面要提权。访客只能读工作目录和系统目录，也不能提权。
- 命令结束时，它启动的后台进程会被清理。

## 在聊天里配置网关

管理员会话有两个网关工具，不用守着网页：

- `Gateway`：查询网关状态、内核和机器、模型和接口（只有 `has_key`）、SSH 连接（只有 `has_password`）、工作目录、电脑配对、`~/.ssh/config` 里的别名，或最近几行脱敏日志（`{"what":"logs","lines":50}`）。不审批。
- `GatewayAdmin`：添加/修改/删除模型接口和模型、从接口拉模型列表、设默认/测试/切换本会话模型；保存/删除/连接/断开 SSH，`ssh_setup` 一步保存、连接、等在线并可添加挂载工作目录；添加/删除/挂载工作目录；允许/拒绝/移除电脑配对；`restart` 检查配置后重启网关。**每次修改都要审批，auto 模式也一样**，审批卡片标题带“提权”，密码和 key 打星。

它直接调用网页接口背后的函数，改完立即生效，不用重启网关（`restart` 除外）。监听地址、网页密码、渠道 token、内核口令这类要重启的配置不开放给 AI。密钥可以就在聊天里给，落盘走上面的加密，工具结果和审计日志不回显。仓库里带了 `device-connections` 和 `model-setup` 两个技能，教模型先查清楚再动手。

## 管理员

- **把自己设为管理员**：先私聊机器人说一句话，然后在网页里点拓扑图上的「飞书」或「Telegram」，“聊过天的人”里找到自己，点「设为管理员并接到主会话」。也可以手动写进 `gateway.toml` 的 `[access] admins`（比如 `"tg:123456789"`、`"feishu:ou_xxx"`），自己的身份在聊天里发 `/whoami` 查看。命令行和网页用户始终是管理员。
- 不是管理员时，`/session` 只显示自己的会话，并提示怎么成为管理员。
- 只有管理员能用写文件、执行命令这类工具，能改工作目录和模式，能审批。
- 其他人默认只能聊天（`guest = "none"`）；设成 `readonly` 的话可以读工作目录里的文件和搜索。
- 需要审批时，bot 会在聊天里发一条 `⚠️ 需要审批 #3`，写清楚在哪个工作目录上执行什么命令、改什么文件。Telegram 和飞书里下面直接带「批准 / 拒绝」按钮，点一下就行（也可以回复 `/approve 3`、`/deny 3`，或者在网页上点）；在哪儿批了，所有窗口里的审批消息都会改成结果。超时（默认 300 秒）按拒绝处理。

## 会话和聊天窗口

**会话**是一段对话：上下文、工作目录、权限模式、思考强度、人格。**聊天窗口**是终端、你和 Telegram 机器人的私聊、你和飞书机器人的私聊。每个窗口接在一个会话上，一个会话可以同时接好几个窗口：

- 管理员的窗口默认都接在**主会话**上：终端、网页、Telegram、飞书共用同一段上下文，接在同一会话的窗口自动同步用户消息和回复，并标明来源。
- 其他人私聊机器人，各自一个会话，互相看不到，也看不到主会话。
- 每条用户消息前的时间戳里写着来源（`[2026-10-21 周三 15:08 · Telegram]`），模型知道你是从哪儿说的。
- 想开一段新的对话：`/session new 名字`，这个窗口就接到新会话上了；`/session` 列出所有会话，`/session 1` 切回主会话。网页里点“新建会话”，或者在会话设置里把某个窗口改接过来。
- **跨端自动同步**：接在同一会话的终端、Telegram、飞书会自动显示其他端的用户消息和回复，不用先在那个窗口发言。`/history` 或 `/sync` 随时补看最近的对话（`/history 10` 看 10 轮）；即使模型上下文已经压缩，仍能查看原始聊天记录。切换会话、设为管理员和重新接入时也会补上最近的对话，已看位置保存在 `data/endpoints.json`。Telegram 的命令菜单里也能直接找到历史、同步和会话。
- 网页能看到所有会话，也能往任何一个会话里发消息。主会话一直接着网页；在网页里新建或者说过话的会话，也算网页接着（拓扑图里会连上线）。

接线存在 `data/endpoints.json`。从旧版本升级时，原来终端的会话 `cli:local` 会自动并入主会话。

## 聊天命令

| 命令 | 作用 |
|---|---|
| `/help` | 列出命令 |
| `/whoami` | 显示你的身份、这个窗口和它接着的会话（配置管理员、单独人格时要用） |
| `/session` | 列出所有会话；`/session <编号或名字>` 把这个窗口切到那个会话，`/session new [名字]` 新建一个会话并切过去（切换需管理员） |
| `/history`、`/sync` | 查看当前会话最近 5 轮原始对话；加轮数看更多（最多 30 轮）；同一会话内也会自动同步 |
| `/dir` | 查看这个会话挂了哪些工作目录和整个列表；`/dir <编号>` 挂上，`/dir -<编号>` 取下，`/dir add 机器:路径` 添加并挂上（只写路径就是本机，比如 `/dir add gpu:~/proj`），`/dir none` 全部取下（在 HOME 下工作），`/dir default <编号>` 设为 / 取消新会话默认挂载，`/dir rm <编号>` 从列表里删掉（改动需管理员） |
| `/node` | 查看有哪些机器、哪些内核在线，这个会话这一轮由谁执行 |
| `/mode` | 查看权限模式；`/mode auto\|ask\|readonly` 切换 |
| `/think` | 查看思考强度；`/think none\|low\|high…` 切换（`none` 是关闭，可选值跟着这个会话的模型走），`/think default` 恢复模型的默认值 |
| `/model` | 查看这个会话用的模型和所有可用的模型；`/model <编号或 ID>` 切换，`/model default` 用默认模型 |
| `/stop` | 停止当前任务（正在执行的命令会被杀掉）。任务进行中直接发「停」也行；Telegram 回复下面有“⏹ 停止”按钮，终端里按 Ctrl-C（连按两次退出） |
| `/undo` | 撤回最近一条消息：还没处理的直接拿掉；正在处理的先停下再删；已经回复的连同回复、工具调用一起从上下文里删掉。直接发「撤回」也行，网页上最后一条消息旁有“撤回”（内容会放回输入框）。飞书里撤回自己发的消息也会同步撤回（需要订阅 `im.message.recalled_v1`，扫码创建的机器人自动订阅） |
| `/reset` | 清空本会话的上下文（工作目录和模式保留） |
| `/approve <编号>` / `/deny <编号>` | 批准或拒绝一次工具执行 |

目前只支持私聊，群聊以后再做。

## 接入 Telegram

1. 找 [@BotFather](https://t.me/BotFather) 发 `/newbot`，拿到 token，填进 `gateway.toml` 的 `[telegram]`，并设置 `enabled = true`。
2. 国内访问 Telegram 需要代理：`proxy = ""` 表示用网关的默认代理（`[network] proxy`，它留空就跟随环境变量 `HTTPS_PROXY`），也可以直接写 `proxy = "http://127.0.0.1:7890"`。
3. 用的是长轮询，不需要公网地址。私聊机器人就能用（目前只支持私聊）。

回复正文单独发送并持续编辑，默认每秒合并更新一次：模型写的 Markdown（粗体、代码、代码块、链接、列表、引用、表格）转成 Telegram 支持的格式显示，转不了时退回纯文本；长回复按 UTF-16 长度在换行处分段，代码块跨段也不会乱。思考和工具调用放在回复上面一条独立的过程消息里：一行状态（正在思考 / 正在执行某个工具 / 完成），下面是 Telegram 原生的可展开引用，默认收起；处理中带「⏹ 停止」按钮。工具调用很多时只留最近的，完整记录在网页中查看；更新失败时补发正文。

## 接入飞书

用的是飞书开放平台的长连接模式，不需要公网地址，也不用配置加密。

**最简单的办法是扫码创建**：在网页管理界面点拓扑图上的“飞书”节点 → “生成二维码”，用飞书扫一扫、在手机上确认，网关会自动拿到 App ID 和 App Secret、写进配置并启动飞书渠道（走的是飞书开放平台官方的应用注册接口）。创建好之后私聊机器人试试；如果没反应，到开放平台看一下这个应用：事件订阅方式要是“长连接”，并且已经发布了版本。

也可以手动创建：

1. 在[飞书开放平台](https://open.feishu.cn/app)创建企业自建应用，在"添加应用能力"里加上**机器人**。
2. 在"凭证与基础信息"里拿到 App ID 和 App Secret，填进 `gateway.toml` 的 `[feishu]`，并设置 `enabled = true`，然后启动网关。
3. 在"事件与回调"里把订阅方式设为**使用长连接接收事件**。如果保存时提示检测不到连接，确认网关已经在运行，再保存一次。
4. 添加事件 **接收消息 v2.0**（`im.message.receive_v1`）和 **撤回消息**（`im.message.recalled_v1`），按提示开通配套权限。在“回调配置”里同样选长连接，添加 **卡片回传交互**（`card.action.trigger`）：卡片上的「停止」「批准 / 拒绝」按钮要用。还需要的权限：
   - `im:message`、`im:message:send_as_bot`：收发消息；
   - `cardkit:card:write`（创建与更新卡片）：流式回复需要；以前创建的应用要补开这个权限并发布新版本；
   - 读取用户发给机器人的单聊消息：添加事件时会提示；
   - 可选 `contact:user.base:readonly`：读取用户姓名（没有的话用"用户xxxx"代替）。
5. 创建版本并发布（企业里一般要管理员审核），然后私聊机器人。

具体按钮名称以飞书后台为准，后台改版后可能会变。

飞书的每一轮回复是一张 [CardKit 流式卡片](https://open.feishu.cn/document/cardkit-v1/card-element/content)，默认每半秒合并更新一次，正文有打字机效果：最上面是折叠起来的「思考和工具调用」，中间是回复正文（Markdown），下面一行灰色的状态（处理中在做什么、结束后的用量），处理中带「停止」按钮。简单的回答没有思考和工具调用，就只有正文。长回复接着发只有正文的卡片。工具调用很多时只留最近的，完整记录在网页查看。扫码创建的新应用会申请卡片权限；未开通权限或更新失败时补发正文。审批是一张带「批准 / 拒绝」按钮的卡片，处理后卡片变成结果（按钮需要订阅上面的 `card.action.trigger` 回调；没订阅时回复 `/approve` 也行）。

## 密钥和脱敏

nano-agent 自己保存的密钥不会明文落盘：

- 第一次启动时生成 `~/.nano-agent/secret.key`（32 字节，0600）。
- 模型 API key、SSH 密码、网页密码、Telegram / 飞书 token 在 `data/models.json`、`data/connections.json`、`data/config.json`、`data/web.secret` 里存成 `enc:v1:...`，用 AES-256-GCM 加密；读的时候在内存里解密。
- 旧版 `gateway.toml` 里手写的明文密钥，启动时会搬进 `data/config.json`（加密），并把配置文件里那一行改成空值。配置文件里只留一行注释，告诉你去网页设置里改。
- 这能防的是明文出现在文件里（AI 读文件、截图、备份、误传）；防不了有这个账号权限的人，因为 `secret.key` 就在同一块盘上。**不要删 `secret.key`**，删了已加密的密钥就解不开了。

工具结果可以脱敏（`[security] redact`，网页设置里也能改）：

- `off`：不脱敏；
- `public`（默认）：模型接口在外网，或结果发到 Telegram / 飞书时脱敏；内网模型、网页和终端显示原文；
- `always`：发给模型时总是脱敏。

只处理工具结果（`Read` / `Grep` / `Shell` 等的输出），用户自己发的消息不改。网关自己保存的密钥先精确匹配，再按 PEM 私钥、`sk-…`、`ghp_`、AKIA、`xox[bp]-`、JWT、`password = "…"` 等特征兜底；匹配到的值保留前 4 位和后 4 位，中间打星。历史文件存原文，脱敏在组请求时做，同一段内容每次结果一样，不会破坏前缀缓存。

## 机器和工作目录

网关是唯一有状态的中心：上下文、会话、聊天窗口、审批都在网关。内核是无状态的工人，只跑 agent 循环，可以同时连好几个，按 `kernel.conf` 里的 `node` 区分（默认是主机名，名字不能重复）。

**工作目录 = 机器 + 目录**。机器有三种：

| 机器 | 是什么 | 上面要装什么 |
|---|---|---|
| 本机 | 网关所在的机器 | 不用装；有内核在本机跑更好 |
| SSH 服务器 | 网关通过 SSH 连的服务器 | 不用装：网关自动放上执行器 `nano-exec` |
| 电脑 | 装了内核、自己连到网关的电脑（Linux 或 WSL2） | 内核（用安装脚本，见下面） |

不管内核跑在哪里，都能在任何挂在网关上的工作目录里干活，一个会话还可以同时挂好几台机器上的目录。每一轮开始时，网关先挑跑这一轮的内核：第一个挂载的工作目录那台机器上有内核就用它，其次是别的挂载的机器上的，再其次本机的。然后每个工具调用按它的 `workspace` 参数分两种：

- **同机**：工作目录就在这个内核的机器上，内核在本地执行，和单机一样。
- **异机**：工作目录在别的机器上。工具调用交回网关，网关在那台机器上执行：本机直接运行执行器，SSH 服务器走 SSH，装了内核的电脑请它的内核代为执行；结果再交给跑这一轮的内核。权限模式、审批照常由这个内核管；沙箱的范围由网关按工作目录生成，不用内核给的路径。

挂载的工作目录所在的机器用不了时（电脑关机、服务器断开），这一轮先不挂它并告诉模型；全都用不了时如果本机内核在，就在 HOME 下工作；否则这一轮没有工具。机器回来后自动恢复。一个内核都不在线时没法回复。

**本机的内核**由网关自己启动（`[kernel] local`，默认开），名字默认是 `gateway`（`[kernel] local_name`），它用一个每次启动随机生成的口令连回网关，配置在 `data/local-kernel.conf`，日志在 `data/kernel.log`；退出了会自动重启，网关退出时一起停掉。内核断线后会自动重连；断线时它正在跑的那一轮作废（正在执行的命令会被杀掉），聊天里会收到提示，排队的消息交给别的内核。

拓扑图右边列出所有机器，工作目录挂在它所在的机器下面；点机器能看到沙箱、浏览目录、添加工作目录，点工作目录能看到在上面工作的会话。

**SSH 服务器**：在网页“设备”里添加主机、端口、用户和密码，或者直接选网关这台机器 `~/.ssh/config` 里的别名 / 密钥（Include、跳板机、代理照常生效）。点“保存并连接”，网关建立一条 SSH 主连接（ControlMaster），之后每次工具调用、浏览目录都复用它；掉线自动重连，也可以手动断开，或者设成随网关启动。连上后网关检查服务器的架构，把执行器传到服务器的 `~/.nano-agent/`；架构不同（比如 ARM 服务器）时把源码传过去用 `cc` 现编。服务器上不跑内核，不用开端口，也不用能访问到网关。

连接信息存在 `data/connections.json`（0600，密码加密，接口不返回密码）；密码只通过 `SSH_ASKPASS` 交给 ssh，不出现在命令行和日志里。首次连接接受新主机的密钥，密钥变了就拒绝连接。

**在别的电脑上装内核**：内核要在那台电脑上编译（C，只依赖 libc），安装脚本全包了：

```sh
make installer                                         # 在网关这台机器上：生成单文件安装包 dist/nano-kernel-install.sh
sh nano-kernel-install.sh --gateway 192.168.1.2:7700   # 拷到那台电脑上运行
```

脚本检查编译工具，缺了就用包管理器装（apt / dnf / pacman / zypper / apk，用 sudo 之前先问）；编译后装到 `~/.nano-agent/kernel/`，写好 `kernel.conf`，注册 systemd 用户服务（开机自启、退出了自动重启；没有 systemd 的 WSL 用后台进程，可以选择登录时自动启动），然后连上网关请求接入，显示一个 6 位确认码。用 `Gateway {"what":"pairing"}` 看确认码，再用 `GatewayAdmin {"action":"pair_allow","id":"…"}` 允许（网页“设备”里也能点），网关给这台电脑发一个专用口令（存在 `paired.token`），之后自动重连。配对的口令只能用这台电脑的名字，冒充不了别的机器；用 `pair_remove` 或在“设备”里移除，口令就作废。

- 再运行一次就是升级（保留配置和口令）；`--uninstall` 卸载；`--name` 改名字；`--no-service` 只装不启动。
- 装好后用 `nano-kernel status|start|stop|restart|connect|logs` 管理（已加进 PATH；`nano-kernel help` 看全部）。
- 源码目录里可以直接运行 `./scripts/install-kernel.sh`（或者 `make install-kernel`），不用生成安装包。
- 电脑接入要先在“设备”里启用（默认端口 7700，也就是 `kernel.device_listen`）。协议本身不加密，跨网络请走 WireGuard / Tailscale / SSH 隧道。
- Windows 上在 WSL2 里安装，工作目录用 `/mnt/c/...`、`/mnt/d/...`。

聊天里也可以让 bot 调用 `Skill` 读 `device-connections`，它会按这里的说明帮你排查连接问题。

## 模型接入

任何 OpenAI 兼容的 `/chat/completions` 接口都能接，比如 vLLM、DeepSeek、通义、Kimi。请求走流式接口。

- **代理**：接口自己的 `proxy` 留空时用网关的默认代理 `[network] proxy`；它也留空就跟随环境变量。Go 不认 `NO_PROXY` 里 `10.*` 这种通配写法，**内网的模型地址要显式写 `proxy = "none"`**（直连），否则请求会被发到代理上。
- `[llm.extra]` 里的参数会原样合并进请求体。
- **思考强度**：作为顶层的 `reasoning_effort` 原样传给模型（vLLM 等兼容接口也认），`none` 表示关闭。每个模型可以设默认思考强度和可选值；每个会话可以用 `/think` 单独改。不同模型支持的值不一样（比如有的不支持 `medium`）。

### 模型管理

接口和模型只存在数据目录的 `models.json`（0600，API key 加密；网页只显示有没有设置密钥），全部在网页拓扑的「模型」节点里管理：

- **没有模型就是空状态。** 新装第一次打开，模型节点和聊天区都会提示去配置；不会自动造模型、不会拿配置文件凑一个。
- **加接口**：点模型节点 → 顶部「接口」，或者右键画布空白 → 新增接口。填名字、类型、地址（到 `/v1` 为止）、API Key、代理；保存后自动接着加模型。
- **加模型**：选接口，填模型名、上下文窗口（必填）、最大输出、历史上限、默认思考强度和可选值、输入类型（文字/图片）。可以从接口的 `/models` 拉取模型列表，自动填模型名和上下文窗口。
- **默认模型**：新会话、没有单独选模型的会话用它。它只是一个标记，不是等级；随时可以换。
- **测试 / 删除**：面板里可以单独测试连接；模型和接口都可以删。单独选了被删模型的会话回退默认；全删光就回到空状态。
- **旧配置**：`gateway.toml` 的 `[llm]` 里的模型会在升级后第一次启动时一次性导入成普通模型（接口名字取地址里的主机名），之后可以像别的模型一样修改、删除；删了重启不会复活。`[llm]` 以后只保留超时、温度、额外参数、回传思考、裁剪比例这些全局默认。
- 每个会话可以用 `/model` 或会话设置单独选模型。

## 图片输入

可以在对话里发图片：网页上选择、粘贴或者拖进来；Telegram 直接发照片（或者以文件发的图片）；飞书发图片消息。终端里暂时只能发文字。

- 只有**模型支持图片**时才会把图片发给它：在模型节点里给这个模型勾上「图片」。纯文本模型会收到一句 `[图片×N]` 的说明，并提醒你换个模型；图片仍然留在历史里，换成支持图片的模型再聊还能看到。
- 支持 PNG、JPEG、GIF、WebP，单张最多 10 MB，一条消息最多 4 张。图片存在数据目录的 `uploads/`（权限 0600，按内容去重），会话历史里只存引用。
- 图片会一直留在上下文里（压缩摘要时只保留文字说明），聊得久、图片多的时候 token 会涨；不需要了可以 `/reset`。
- 音视频暂时不支持。

## 上下文和前缀缓存

模型服务一般都有前缀缓存：这次请求的开头和上次一样，那部分就不用重新计算，又快又便宜。网关的上下文管理围绕这一点设计——**每次请求都是上一次请求原样加上新消息**：

- 系统提示词（人格）和工具定义固定不变，里面不放时间、目录这类会变的东西。
- 时间和来源写在每条用户消息前面（`[2026-10-21 周三 15:08 · 命令行]`）；工作目录、权限模式变了，就在下一条用户消息前加一句 `[系统] …`。都是追加，不改前面的内容。
- 工具输出在写进历史时就截断定型，思考内容不回传，历史只追加。
- 历史超过这个模型的「历史上限」（没填时按上下文窗口的一半；按字节数粗估）时，**一次**整理最早的一大段，保留 `trim_to` 的比例（默认一半），之后又只追加，直到下次超出；不会每次都裁一点（那样每次请求的开头都不一样，缓存永远不命中）。只在用户消息处切，工具调用和结果不会被拆开，当前这一轮始终完整保留。
- 整理时额外请求一次当前配置的模型，将旧对话与上次摘要合并，保存目标、决定、关键路径、结果和待办；不传工具和推理记录，输出上限 2048 token，可用时关闭思考，最多等 60 秒。摘要和工作目录信息放在剩余历史前面，后续请求保持这个前缀不变，用量计入本轮统计。生成失败时保留已有摘要并注明省略，不阻断正常回复；停止、清空会话也会取消摘要请求。
- 每次模型调用的缓存命中数记在日志里（`cached_tokens`），命令行每轮结束显示命中率。

对话历史存在 `data/sessions/<会话ID>.jsonl`，一行一条消息，只追加，压缩也不改写原始记录；重启后会恢复摘要和保留的上下文。会话设置（名字、工作目录、模式、思考强度、裁剪位置、摘要）在同目录的 `.settings.json` 里，聊天窗口接在哪个会话上记在 `data/endpoints.json`。

## 测试

```sh
make test
```

- `kernel/tests/test_core.c`：状态机单元测试（ASan + UBSan）。
- `kernel/tests/test_exec.py`：直接驱动执行器，测五个工具，以及各种绕过沙箱的尝试（`..`、符号链接、`~`、unix socket、发信号、环境变量里的密钥）。
- `kernel/tests/test_host.py`：用假网关驱动真实的内核和执行器，测权限模式、审批、超时、取消、断线重连、进程清理、工具交给网关执行（ASan 版本）。
- `gateway/...`：Go 单元测试，`internal/app` 里用假内核走真实 socket 测调度逻辑（`-race`）；`internal/host` 用假的 ssh 测部署、执行、断线和现编，有 `sshd` 时再起一个临时的真 OpenSSH 服务器测一遍。
- `gateway/internal/web`：网页接口的测试（登录、防跨站请求、Host 检查、改配置、事件流）。
- `scripts/e2e.sh`：真实的内核、执行器和网关一起跑，模型用 mock，不花钱；包括网关通过（假的）SSH 在服务器目录里执行工具。
- `scripts/e2e-control.py`：临时 `NANO_HOME`、后台进程模式和 mock 模型，测 `version/start/status/logs/url/restart/stop`、聊天 `/status` `/restart`（含坏配置拒绝重启、重启后回话）、网页重启后登录仍有效、看护进程在 `kill -9` 后拉起，共 12 项；不碰真实 `~/.nano-agent`、仓库里的 `gateway.toml`/`data/` 和真实的 `nano-gateway.service`。

前端代码在 `gateway/web/`（Svelte + Vite），构建结果放在 `gateway/internal/web/dist/` 并提交在仓库里，编译网关只需要 Go。改了前端之后运行 `make web` 重新构建（需要 Node 20 以上）。

加一个类型是 `mock` 的接口就能不接模型调试整条链路：消息里写 `!call 工具名 {参数}` 会让假模型去调这个工具，比如 `!call Shell {"command":"ls"}`。
